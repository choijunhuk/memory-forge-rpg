# P0-1 사람 플레이 시험 키트

설계서 §20 P0-1의 기준: 프로토타입 플레이 기록 10판 이상과 설문(재미·난이도·예약/균열 이해도). 통과 기준은 예약·균열 이해 80%, "다시 하고 싶다" 70%다. 담당은 디렉터(사용자)다. 이 키트는 그 시험을 같은 방식으로 반복하고 결과를 숫자로 모으기 위한 것이다. 봇·자동 시험·Editor 조작은 이 시험을 대신하지 않는다.

## 1. 준비

- **PC(macOS):** `ops/ai/local/builds/MemoryForge-PC-<날짜>.app`을 더블클릭한다. 최신 빌드는 루트 세션이 만든다.
- **Android:** `adb install -r ops/ai/local/builds/MemoryForge-dev-<날짜>.apk`
- 참가자마다 새로 실행한다. 로컬 연습판은 앱을 닫으면 진행이 사라지므로, 앱을 껐다 켜면 처음 상태가 된다.
- 지금 화면은 그림·애니메이션이 없는 개발용 UI다. 시각 디자인 1차안이 들어간 빌드로 시험하는 편이 결과가 더 의미 있다. 지금 빌드로 할 때는 기록의 `build` 칸에 적는다.

## 2. 진행 (참가자 1명당 약 20~30분)

1. 진행자는 규칙을 설명하지 않는다. "화면 안내만 보고 해 보세요"라고만 말한다. 질문이 오면 "화면에서 찾아보세요"라고 답하고, 3분 넘게 막히면 한 번만 힌트를 주고 기록한다.
2. 짧은 탐사(1구역) 한 판을 끝까지 하거나 패배할 때까지 한다.
3. 진행자는 아래 관찰 항목을 기록한다.
4. 끝나면 설문을 바로 한다(아래 §4). 이해도 문항은 정답을 알려 주지 않는다.

## 3. 관찰 항목 (진행자 기록)

| 항목 | 기록 |
|---|---|
| 완주 여부·결과 | 완주/패배/중단, 도달한 층 |
| 걸린 시간 | 분 |
| 첫 카드 사용까지 걸린 시간 | 초 |
| 예약(다음 턴·다다음 턴)을 스스로 썼는가 | 예/아니오, 처음 쓴 턴 |
| 균열을 노리고 약점 속성을 골랐는가 | 예/아니오/모름 |
| 막힌 곳 | 화면, 무엇을 찾았는지, 힌트를 줬는지 |
| 참가자가 한 말 | 그대로 적는다 |

## 4. 설문 (참가자 작성)

1. 재미: 1(전혀) ~ 5(매우)
2. 난이도: 1(너무 쉬움) ~ 3(적당) ~ 5(너무 어려움)
3. **예약 이해도.** "다음 턴"으로 예약한 카드는 언제 효과가 나나요? (하나)
   - (a) 고르자마자 바로
   - (b) 다음 내 턴이 시작될 때
   - (c) 적이 행동한 직후
   - (d) 전투가 끝날 때
4. **균열 이해도.** 적의 균열 게이지가 0이 되면 어떤 일이 생기나요? (해당하는 것 모두)
   - (a) 그 적의 다음 행동 1회가 취소된다
   - (b) 그 적이 받는 피해가 늘어난다
   - (c) 다음 턴 내 행동력이 늘어난다
   - (d) 그 적의 체력이 회복된다
5. 이 게임을 다시 하고 싶나요? 예/아니오
6. 가장 헷갈렸던 것, 가장 재미있었던 것 (자유)

정답(진행자만 본다): 3번은 (b). 다음 턴 시작에 만기 예약이 해결된다(§5 턴 순서). 4번은 (a)(b)(c)를 모두 고르고 (d)는 고르지 않아야 한다(§5.6).

## 5. 기록과 집계

참가자마다 `reports/playtest_p0_1/records/<날짜>-<참가자번호>.json`을 [record.template.json](record.template.json) 형식으로 만든다. 이름·연락처 같은 개인정보는 넣지 않는다.

```bash
python3 tools/playtest/aggregate_p0_1.py reports/playtest_p0_1/records
```

출력은 기록 수, 예약 이해율, 균열 이해율, 재플레이 의향, 평균 재미·난이도, 기준 통과 여부다. 이해율은 정답 참가자 비율이며 4번은 정확히 (a)(b)(c)일 때만 정답으로 센다. 10판 미만이면 통과로 표시하지 않는다.
