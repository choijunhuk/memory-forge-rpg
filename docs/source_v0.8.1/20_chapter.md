# <a id="ch20"></a>20. Claude·Codex·Unity MCP 제작 실행 계획

## 20.1 읽기 순서와 실제 기준

두 에이전트 모두 `AGENTS.md` → `docs/CURRENT.md` → `docs/design_v0.8.1.md` → `reports/audit_v081/status.json`을 읽는다. 숫자·카드 정의는 현재 `data/game_data.json`, 실행 참조는 `engine/rules-core.js`다. `data/design_policy_v0.8.json`은 목표 정책과 활성 상태를 분리한 계약이다. 이 파일을 읽었다는 이유만으로 게임 규칙이 바뀌지는 않는다.

## 20.2 역할과 편집권

| 영역 | 작성 | 검토 | 병렬 작업 조건 |
| --- | --- | --- | --- |
| 전투·저장·서버 | Codex | Claude + 회귀 시험 | API/상태 계약을 먼저 고정 |
| UI·콘텐츠·문서 | Claude | Codex + 화면 시험 | 데이터 필드 이름과 오류 코드 공유 |
| 경제·과금 | 한 에이전트가 제안 | 다른 에이전트 독립 계산 + 사람 승인 | 같은 수급표를 서로 다른 방식으로 검산 |
| 아트·서사 | Claude 또는 아트 담당 | 사람 + 캐릭터 일관성 검수 | 나이·직책·의상·대사 원본 변경 이력 |
| Unity MCP | 편집권을 가진 한 작업자 | 결과 스크린샷·씬 diff | 같은 씬·프리팹 동시 수정 금지 |

각 작업은 별도 브랜치와 worktree를 쓴다. 씬 편집권 파일에는 프로젝트 경로, 작업자, 작업 범위, 시작 시각, 만료/반납을 기록한다. 잠금은 충돌을 줄이는 작업 규칙이지 운영 권한이나 보안 경계를 대신하지 않는다. MCP 서버와 Unity 패키지 버전은 검증한 조합으로 고정하고 연결·Play Mode·파일 생성 로그를 남긴다. 프로젝트 밖 파일·실사용자 데이터·운영 비밀키를 읽도록 허용하지 않는다.

## 20.3 P0: 저장 정책을 실제 흐름으로 연결

Codex는 안정적 카드 key·출발 스냅샷·종료 diff·최종 비용·이관 어댑터를 구현한다. Claude는 ‘기존 기억 유지’ 기본 선택, 신규 변화 0~1개, 용량 초과 이유, 전후 미리보기를 연결한다. 두 작업자는 같은 요청 DTO와 오류 코드를 쓴다.

통과 조건은 독립 모듈 시험만이 아니다. 기존 저장 덱으로 탐사 시작 → 패배 → 선택 없이 이전 덱 유지, 신규 변화 하나 저장, 최종 용량 초과 거절을 실제 HTML 클릭으로 확인한다. 재로딩·동일 요청 재전송·두 같은 종류 카드·진화와 강화의 분리 선택을 검사한다. 이 조건을 통과한 뒤에만 HTML의 저장 v2 미연결 경고를 제거한다.

## 20.4 P1: C#·서버

C# Battle·Run·저장 로직은 검증된 JS 동작을 netstandard2.1/C# 8의 제한 안에서 이식한다. 기존 RNG·가챠·스탯·예약 장부의 검사 수를 전체 전투 완성으로 해석하지 않는다. 정수/BigInteger 반올림·컬렉션 순회 순서·직렬화 필드 순서를 정의하고 같은 시드·명령에 대해 명령별 상태 해시를 비교한다.

서버는 계정·콘텐츠 버전·모집·성장·탐사·전투·기억 저장 API를 구현한다. 계정 잠금 → 요청 해시/멱등 확인 → 규칙 → 상태·원장·이력 → 영수증 → 커밋의 일관된 계약을 지킨다. DB 스키마의 기존 제약 검사는 서버의 거래 검증과 별도다.

## 20.5 P2: 콘텐츠와 화면

후반 여섯 행동의 효과·의도·실패 경계를 먼저 구현한 뒤 3~5구역 적을 연결한다. 전투 준비, 대본 준비, 아트·음성 준비를 각기 다른 플래그로 둔다. 본편 인장 6개·인연 20조각·기록 균열 팀 완화·무료 용량 변경을 데이터와 화면에 동시에 반영한다.

Unity에서는 로비 → 편성 → 지도 → 전투 → 보상 → 저장을 실제로 한 판 이어간다. 큰 글자·최대 손패·예약·최대 적·앱 복귀·통신 끊김을 검사한다. 실기기의 조작성과 성능은 브라우저 픽셀 검사와 분리한다.

## 20.6 P3: 상용 운영 전환

월정액·패스·상점·영수증 검증·환불 상태·공지·고객지원·운영 도구를 연결한다. local/dev/staging/production의 계정·DB·키·재화를 분리한다. 테스트 결제가 production 지급으로 넘어가지 않게 발급자·상품·환경을 확인한다. 원격 production 배포·실결제 검증은 별도 사람 승인 후 수행한다.

## 20.7 완료 보고 양식

| 필드 | 작성 내용 |
| --- | --- |
| 변경 범위 | 실제 파일·규칙·데이터 버전 |
| 실행 명령 | 작업 디렉터리·명령·종료 코드 |
| 재현 | 시드·상태 스냅샷·콘텐츠 해시 |

| 미완료 | 이식·연결·성능·아트·결제 중 남은 것 |
| 다음 단계 | 새 작업자에게 필요한 정확한 파일과 인수 조건 |

PR에서 작성자가 아닌 에이전트가 수정 이유와 반례를 검토한다. ‘모두 완료’, ‘완벽’, ‘버그 없음’ 대신 통과한 범위와 아직 하지 않은 작업을 쓴다. 원격 저장소를 만들거나 푸시한 사실은 실제 작업이 있을 때만 보고한다.

> 아래 원본 P번호는 작업 식별자 보존용이다. 실행 순서는 위20.3의 저장 연결 → 후반 행동/이식 → 서버/Unity이며, 과거 표가 이 순서를 덮어쓰지 않는다.

## 20.9 원본 작업별 상세 지시 — 현재 우선순위로 실행

### P1-1 (Codex) — C# 전투·탐사 이식

```text
저장소 memory-forge-rpg에서 작업한다. 먼저 AGENTS.md, docs/design_v0.8.1.md의 §5(전투), §7(탐사), §8(기억 저장), §16.2를 읽어라.
목표: engine/rules-core.js의 Battle·Run·memoryChanges·commitMemory를 core/MemoryForge.Core(netstandard2.1, C# 8, 외부 패키지 없음)로
1:1 이식한다. 부동소수점 금지(정수·System.Numerics.BigInteger), 반올림은 JS와 같게(Math.round 동치 = (2a+b)/(2b), 내림 = 정수 나눗셈).
1) tools/gen_traces.mjs를 새로 만들어 JS 무작위 봇으로 시나리오 1,000개(짧게 700·정규 300)의 {seed, party, 명령열, 명령별 상태 해시}를
   engine/tests/vectors/traces.json으로 저장한다. 상태 해시 = 키 정렬 JSON의 SHA-256(로그 필드 log·ev 제외).
2) C#에 같은 직렬화와 해시를 구현하고 CoreChecks에 trace 재생 검사를 추가한다.
3) 완료 조건: dotnet run --project core/MemoryForge.CoreChecks -- . 가 기존 202개 + trace 1,000개 전부 통과. node --test 그대로 통과.
결과 명령과 출력 요약을 reports/csharp_checks.txt에 남겨라. 규칙이 문서와 엔진에서 다르면 엔진을 바꾸지 말고 docs/decisions.md에 질문을 남겨라.
```

## 20.10 저장소 규칙

- 브랜치: `p1-core`, `p1-server`, `p2-zones`, `p3-client`… 작업마다 PR, CI(§18.2) 통과 필수.
- 커밋 전: `node content/build.mjs data && node tools/gen_vectors.mjs && node tools/gen_docs.mjs` 후 변경분까지 함께 커밋(생성물 불일치 금지).
- 보고: 실행한 명령, 결과, 시드, 바꾼 규칙, 하지 않은 것을 PR 본문에 적는다. "소스 작성·컴파일·단위 시험·Play Mode·실기기"를 구분한다.
