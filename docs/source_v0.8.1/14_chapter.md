# <a id="ch14"></a>14. UI·UX

브라우저 프로토타입(`prototype/`)이 화면 흐름과 상태 처리를 실제로 구현한 참조다. Unity 클라이언트는 같은 흐름을 가로 화면(16:9)으로 옮긴다.

## 14.1 정보 구조

```wire
로비 ─┬─ 탐사 ─ 편성 ─ 지도 ─ (전투 | 보상 | 휴식 | 공방 | 상점 | 사건 | 기록소) ─ 기억 저장 ─ 결과
      ├─ 스토리(장 선택 → 탐사)        ├─ 이벤트(스토리·탐사·고난도·상점)
      ├─ 도전(주간 보스 · 기록 균열 · 성장 던전)
      ├─ 모집(배너 탭 · 확률표 · 기록) ├─ 캐릭터(목록 → 상세: 정보·성장·스킬·장비·무기·공명·인연·기억 덱)
      ├─ 무기 · 기억 덱 · 도감(캐릭터·카드·무기·유물·적)
      ├─ 임무 · 패스 · 우편 · 상점 · 설정
```

## 14.2 공통 규칙

| 항목 | 규칙 |
|---|---|
| 터치 영역 | 최소 48dp(카드 손패 높이 최소 120dp, 가로 화면 기준) |
| 글자 | 본문 14sp 이상, 카드 효과 12sp 이상, 숫자는 고정폭 숫자 서체. 글자 크기 100/115/130% 설정 |
| 색 | 다크 단일 테마. 토큰: 바탕 #0d1322, 패널 #141c31, 선 #2f3d63, 본문 #e9eef8, 보조 #98a5c0, 황동(주 행동) #e2b45f, 기억(예약·시간) #62d6c6, 위험 #ff6f6f. 속성: 전격 #ffd84d · 화염 #ff7a3d · 빙결 #7cc8ff · 공허 #b68cff |
| 색 의존 금지 | 속성·상태는 색 + 아이콘 + 글자를 함께. 예약 칸은 점선 테두리, 봉인은 빗금 |
| 글꼴 | 제목 Hahmlet, 본문 IBM Plex Sans KR, 숫자 Orbit(모두 OFL). 게임 빌드에 폰트 파일 포함 시 라이선스 사본 동봉 |
| 움직임 | 동작 줄이기 설정 시 카드 이동·피해 숫자 애니메이션 생략 |
| 피드백 | 모든 거절은 오류 코드별 한국어 문구(부록 §23.2)로 2.6초 토스트, 버튼 비활성 사유는 버튼 안 보조 문구 |
| 미리보기 | 카드 버튼에 "이 방식으로 쓰면" 예상 피해·방어·회복·균열을 표시(현재 상태 사본에서 실제 엔진으로 계산) |

## 14.3 전투 화면 (가로 16:9)

```wire
┌ 상단 ─────────────────────────────────────────────────────────────
│ 파티 체력 243/243 · 3턴 · [방어 12] [반격 2] [부채 2] [잔향 1/3]      행동력 ●●●○ 3
│ [뽑을 13] [버림 4] [소멸 1]                                          [설정]
├ 전장 ─────────────────────────────────────────────────────────────
│ 세라 ▓▓▓░ [필살]   │ 적1 기억 나방 18/18 · 균열 ■■□ · 약점 전격·화염 · 이번: 공격 12 · 다음: 7×2
│ 하린 ▓░░░ [필살]   │ 적2 톱니 병정 24/24 · 균열 ■■■■ · 약점 전격·공허 · 이번: 방어 6 · 다음: 공격 18
│ 니아 ▓▓░░ [필살]   │
├ 시간표 ───────────────────────────────────────────────────────────
│ 다음 턴 [시한 포격] [빈 칸] [ - ]        다다음 턴 [빈 칸] [ - ]
├ 행동 ─────────────────────────────────────────────────────────────
│ 선택: 시한 포격 → [다음 턴 예약 · 비용 2 · 피해 22 균열!]  [다다음 턴 · 비용 2 · 피해 30]
│ 손패: [유리탄 1] [엄폐 사격 1] [정조준 1] [시한 포격 2] [단검 찌르기 1]          [턴 종료]
└───────────────────────────────────────────────────────────────────
```

| 상태 | 화면 |
|---|---|
| 기본 | 카드를 누르면 선택(위로 4px), 사용 방식 버튼과 미리보기 표시 |
| 대상 필요 | 대상 가능한 적에 기억색 테두리, "적을 눌러 대상을 고르세요" 안내. 적 1체면 자동 |
| 고정 대상 | 표식 없는 적은 누를 수 없음(누르면 사유 토스트) |
| 선택 효과 | 소멸·버리기·조정·회수 등은 모달에서 카드 선택(자동 선택 버튼 포함) |
| 사용 불가 | 손패 카드 흐리게(모든 방식이 검사 실패), 방식 버튼 비활성 + 사유 |
| 필살기 준비 | 게이지 100이면 필살 버튼 강조, 대상 필요 시 적 선택 |
| 적 행동 중 | 입력 잠금, 피해 숫자 팝업, 균열 시 "균열!" 연출과 의도 아이콘 교체 |
| 예약 해결 | 턴 시작에 예약 칸에서 카드가 날아가 해결되는 연출(0.3초/장, 건너뛰기 가능) |
| 기록 | 전투 기록 패널(최근 40줄): 사용·예약·피해·균열·처치·상환 |

세로 화면(웹 프로토타입 모바일): 손패·행동·턴 종료를 하단 고정 도크로 둔다. Unity 빌드는 가로만 지원한다.

## 14.4 화면별 명세

| 화면 | 핵심 요소 | 상태·예외 |
|---|---|---|
| 로비 | 캐릭터 1명(인연 대사), 재개 버튼(진행 중 탐사), 일일 임무 진행, 이벤트 배너 | 진행 중 탐사가 있으면 "이어 하기"가 첫 행동 |
| 탐사 편성 | 캐릭터 카드(속성·무기·공명·역할·10대/성인 표시 없음), 3명 선택 순서, 무기 선택(같은 종류만), 길이·난이도, 저장 덱/기본 덱 | 같은 무기 중복 장착 불가, 미보유 잠금 |
| 지도 | 층별 노드, 갈 수 있는 노드 강조, 지나온 길 황동색, 범례 | 노드 진입은 확인 없이 즉시(되돌리기 없음 안내 1회) |
| 보상 | 동전, 진화 분기, 카드 3택 1(+받지 않기 동전 15), 유물, 부품 | 진화는 건너뛰기 가능 |
| 휴식·공방·상점·사건 | §7.3 | 동전 부족·대상 없음 사유 표시 |
| 기억 저장 | §8.6 | 용량 초과·패배 2개 이상 저장 불가 |
| 모집 | 배너 탭, 키아트, 천장 막대(소프트 시작 표시), "다음 SSR 픽업 확정" 상태, 1회/10회 버튼(모집권·결정 표시), 확률표 링크, 결과 화면(희귀도·NEW·공명/정련·픽뚫), 기록 | 결정 부족 시 상점 이동 제안, 연출 건너뛰기 |
| 캐릭터 상세 | 탭: 정보·성장(레벨/승급)·스킬·장비·무기·공명·인연·기억 덱 | 성장 버튼은 비용·결과 미리보기 후 실행 |
| 도감 | 캐릭터 시트, 카드 전체(효과 자동 텍스트), 무기, 유물·부품, 적(행동 순환) | 미발견 항목은 실루엣 |
| 설정 | 글자 크기, 동작 줄이기, 음량, 언어, 계정 연동, 데이터 삭제 요청 | 데이터 삭제는 2단계 확인 + 30일 유예 |

## 14.5 온보딩 순서

1. 프롤로그 1전투: 카드 지금 사용만(행동력·손패 설명).
2. 2전투: 다음 턴 예약 + 적 의도 2개 보기.
3. 3전투: 약점·균열 + 필살기.
4. 보스: 다다음 턴 예약 + 균열 타이밍 맞추기(실패해도 승리 가능한 수치).
5. 첫 기억 저장(용량 6 중 3 쓰기 안내), 니아·하린·리엔 지급.
6. 초심자 모집 10회(모집권 지급) → 2장 해금 시 공방(변주)·계약 소개, 3장 전 주간 보스 소개.

각 단계는 "설명 1문장 + 직접 해 보기"로 구성하고, 설명 텍스트는 3줄을 넘지 않는다. 건너뛰기를 허용하되 기억 저장 안내는 건너뛸 수 없다.

## 14.6 접근성·현지화

- 텍스트는 모두 키 기반(`ui.battle.endTurn`), 카드 텍스트는 효과 데이터에서 언어별 생성기로 만든다(직접 번역 문자열 금지).
- 한국어 기준 길이 + 영어 140%·일본어 100% 여유로 레이아웃을 검사한다.
- 색약 모드: 속성 아이콘 모양 구분(번개·불꽃·눈송이·고리) 유지, 붉은/초록 대비 대신 밝기 대비.

## 14.7 정보 밀도와 안전한 입력

테스트 최악 조건은 손패 10장·예약 5슬롯·적 5명·유리 성장·라비엔 부채·다수 상태·큰 글자 모드다. 작은 화면에서는 예약 슬롯을 줄이지 않고 현재 만기 그룹을 펼치며 다른 그룹은 사용량과 중요 경고를 요약한다. 행동력 차입은 HP 근처의 `다음 AP 4→2`, 성장치는 해당 카드의 핍으로 보여준다.

카드 선택 → 방식 선택 → 대상/슬롯 미리보기 → 확정은 서로 다른 상태다. 첫 탭이나 드래그 손 떼기만으로 의도하지 않은 소비가 일어나지 않는다. 확정 전 취소는 비용 0. 미리보기는 상태 사본에서 계산하고 숨겨진 드로우·난수를 노출하거나 소모하지 않는다. 요청 후 네트워크가 끊기면 동일 requestId로 조회하며 이중 사용을 막는다.

브라우저 픽셀 검사는 모바일 실기기 터치 검증을 대신하지 않는다. 48dp, 글자 배율, 안전 영역, 양손·한손 사용, 손가락 가림은 Unity 실기기 단계에서 별도 통과해야 한다. 미연결 기능의 버튼은 ‘완료’처럼 보이게 하지 않고 개발 상태를 명시한다.

## 14.8 작은 화면의 기존 관찰과 추가 인수 시험

> **출처·상태:** v0.7.1 검토서 35쪽을 이 장에 통합. 아래 재현 수치는 해당 검토의 기록이며, 이번 재실행 결과는 §19.1 및 reports/audit_v081에서 별도로 확인한다. 목표·제안은 실행 완료가 아니다.

<img src="../prototype/tests/shots/battle-390.png" alt="390폭 모바일 브라우저 화면" class="phone-shot" />

오른쪽은 이번 390폭 캡처다. 손패는 가로 스크롤이고 하단 행동 버튼은 고정된다. **캡처에서 상단 체력 줄 일부가 고정 내비게이션과 겹쳐 보인다.** 스크롤 위치·sticky 헤더·안전 영역을 재확인해야 한다.

스크립트의 가로 넘침 검사를 통과했다고 상하 겹침까지 없다는 뜻은 아니다. 손패의 일부가 옆으로 보이는 것은 스크롤 의도일 수 있지만, 핵심 체력 정보가 가려지는 것은 별도 검사 대상으로 남긴다.

#### 추가 인수 시험
1. 화면 전환·대상 선택 뒤 스크롤 복귀 위치가 일정하다.
2. 헤더가 체력·현재 비용·확정 버튼을 가리지 않는다.
3. 카드 확대는 손가락 아래가 아닌 읽을 수 있는 위치에 뜬다.
4. 예약 그룹을 접어도 미해결 개수·발동 순서는 보인다.
5. 가로 640×360, 노치, 글자130%에서 핵심 버튼이 누를 수 있다.

브라우저 세로 화면과 Unity 가로 화면은 별도 산출물이다. 이번 캡처를 ‘안드로이드 실기기 48dp 검증’으로 소개하지 않는다.
