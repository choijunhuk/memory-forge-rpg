### 먼저 읽을 부분

전투·카드·캐릭터는 06~12절, 맵·패배·모드는 13~20절, 모든 육성 비용은 21~30절, 스토리·퀘스트·BM은 31~47절, UI·서버·AI는 48~68절에 있다. **69~84절에는 이번 검토의 채택표, 숫자 비교, 코드 결함, 실제 시험 결과, 구현 작업 단위가 있다.** 패스 1~50레벨 표는 ZIP에 보존하고 PDF 부록에도 수록했다.

외부 검토가 지적한 수익·화면·제작 리스크는 타당한 질문이다. 그러나 87회가 80회 천장을 여전히 넘는다는 사실, 초기 배너 종료 전 수급 시점, 3배에 가까워지는 HP, 구현되지 않은 C# 효과는 별도로 바로잡아야 한다. [I05:35~56,76~129,203~205]

이 문서의 ‘채택’은 **이번 제안서의 개발 기준선**을 뜻한다. 사용자 승인, 유료 출시, 실제 운영 설정 적용을 의미하지 않는다.

### 메인 차별화는 두 가지

A 예약: 지금 쓸 자원을 먼저 지불하고 미래 효과를 설계한다. C 개조: 캐릭터의 고유 기술을 유지하면서 시간·전달·부가 효과를 바꾼다. E 진화와 F 계약은 별도 공통 게임이 아니라 이 규칙을 캐릭터별로 이용하는 방법이다.

## 05. 영구 성장과 탐사 성장을 분리한다

| 층위 | 저장되는 정보 | 초기화 기준 |
| --- | --- | --- |
| 계정 | 캐릭터·레벨·무기·장비·호감도·재화·해금 | 계정 삭제 외 자동 소실 없음. 시즌 변경도 유지. |
| 설계도 | 고유 카드 구성·회로·각인·무기 모드·태그 | 사용·패배로 삭제되지 않음. 버전 이력 보유. |
| 탐사 | 임시 추가 카드·유물·진화·계약·체력·길 | 완주·정상 귀환·포기·패배로 종료. |
| 전투 | 손패·버림·소멸·예약·적 의도·상태 | 전투 종료. 탐사 체력·임시 덱 변경만 상위에 반영. |

한 판의 흐름: 공방 편성 → 탐사 지역·보상 성향 선택 → 경로 선택 → 전투·사건 → 카드 개조 → 중간 기록소 → 보스 → 설계도 확인·보상 확정. 다음 탐사를 새로 시작할 때는 임시 덱이 아니라 계정의 출발 구성으로 돌아간다.

> 전리품을 저장한다는 느낌은 유지하되, 카드의 수치가 무한히 누적되는 구조는 막는다. 발견한 부품과 조립법은 계정에 남고, 해당 탐사의 +강화·유물·E형 진화는 사라진다.

## 06. 전투의 기본 수치와 명령 처리 순서

| 항목 | 기본 규칙 |
| --- | --- |
| 편성·시작 덱 | 3인. 고유 카드 4장×3 + 무기 카드 3 + 공통 카드 3 = 18장. |
| 고유 카드 선택 | 각 캐릭터 대표 2장 고정, 나머지 2장은 해금 풀에서 선택. 동일 정의 최대 2장. |
| 행동력 | 턴 시작 4, 최대 9. 기본 잔여 행동력은 이월하지 않음. 계약 부채를 먼저 정산. |
| 손패 | 턴 시작 5장, 최대 10. 초과 카드는 공개 후 버림. 예약·소멸 카드는 재셔플에서 제외. |
| 필살기 | 각자 0~100.0. 카드 해결 시 기본 +10.0, 턴 +30.0 상한. 소유 캐릭터당 전투 1회. |
| 공유 체력 | 탐사 전투 사이 유지. 새 탐사에는 해당 모드의 초기화 정책 적용. 전투 방어는 다음 내 턴 시작 제거. |
| 판정 단위 | 카드 전체가 아니라 **순서가 있는 효과 하나**. 치명 피해 직후 종료되어 뒤의 회복은 실행되지 않음. |
| 계산 표현 | 정수·basis point(1%=100). 소수 게이지는 0.1 단위 정수. 표시용 반올림은 판정에 재사용하지 않음. |

### 턴 전이

`CREATED → 시작 처리 → PLAYER → RESOLVING → 다음 턴 시작 처리 → PLAYER` 순서다. 시작 처리는 최초 `begin` 한 번 또는 유효한 `end_turn`의 내부 전이로만 실행한다. 플레이어가 StartPlayerTurn을 임의로 반복 호출할 수 없다.

시작: 이전 방어 제거 → 절대 턴 기준 상태 만료 → AP 4와 상환 정산 → 도래한 예약을 발동 순서대로 해결 → 시작 패시브 → 5장 드로우 → 적 의도 확정 → 입력. 종료: 손패 정리 → 절제 계약 성립·파기 확정 → 살아 있는 적의 순차 행동 → 종료 상태 피해 → 다음 턴으로 이동. 각 원자 효과 뒤에 승패를 확인하며 종료 상태에서 추가 턴으로 넘어가지 않는다.

### 명령의 원자성

서버는 계정 권한·전투 소유권 확인 뒤 request_id, expected_version, phase, 카드 소유·존, 대상, 예약 가능 여부, 비용·부채·슬롯을 확인한다. **검증 실패 시 체력·비용·카드·난수 모두 그대로**다. 동일 ID와 같은 본문 재전송은 같은 응답을 돌려주고, 다른 본문 재사용은 충돌이다.

승리·패배 시에도 처리 중인 카드와 대기 예약의 존을 보존한다. 적을 모두 처치한 카드가 손패·버림·소멸 어디에도 없는 ‘유령 카드’가 되면 안 된다. 효과 목록은 데이터에 순서를 명시하며 enum 비트 플래그의 작성 순서에 의존하지 않는다. 보스 페이즈·전 유물은 전체 구현 단계의 추가 항목이다.

> ZIP의 Python 엔진은 이 규칙의 P0 부분집합을 실행한다. 게임의 모든 패시브·적 패턴·전체 필살기를 구현한 것은 아니다. C#은 수식·예약·계약 등의 분리 커널이며 완성 엔진이 아니다. 74·81절 참조.

| 확정 | 비용은 현재 즉시 지불. 취소는 확정 전만 무료. 확정 뒤 순서·대상·회로를 바꾸지 않음. |
| 저장 | due_turn=현재 턴+1 또는 +2, slot_order=고유 순번. 상대 offset만 저장하여 중복 감소시키지 않음. |
| 해결 | 같은 due_turn 안에서 slot_order 오름차순. 예약 카드의 사용 횟수·필살기 게이지는 해결 시 갱신. |
| 일반 공격 | 확정 시 살아 있는 적을 선택. 해결 전에 죽었다면 살아 있는 적의 화면 순서로 자동 전환. |
| 고정 표식 | 확정·해결 시 지정 대상과 표식을 검증. 대상 사망·표식 만료는 불발, 비용 환급 없음. |
| 방어·회복 | 공유 파티에 적용. 이미 확정된 패배를 회복으로 되돌릴 수 없음. |
| 계약 카드 | 차입·유예·절제·담보는 즉시 사용만. 미래 부채 검증을 건너뛰는 예약은 금지. |
| 시간 당기기 | 선택한 예약 1개를 1턴 앞당김. 목적지 용량·봉인도 검증. 현재 턴에 도착하면 같은 효과 큐에서 해결. |

### 용량과 봉인

슬롯 용량은 대상 턴 기준으로 판단한다. 다다음 턴 카드가 다음 턴으로 이동했다고 이미 예약한 카드가 삭제되지는 않는다. 새 예약은 만석이면 거절한다. 담보는 빈 다음 턴 슬롯 하나를 잠그고, 기존 카드를 밀어내지 않는다. 잠금은 **다음 내 턴 종료까지** 유지한다. 여러 담보 중복은 P0에서 금지하고 이후 별도 정의한다.

고정 표식 카드의 미래 결과를 확정적으로 알 수 없으면 ‘조건부’로 표시한다. 예약 표시 숫자는 현재 공개 상태 기준 예상값이며 이후 약화·표식·방어 변화로 달라질 수 있다. 알 수 없는 드로우나 적 패턴을 정확한 미래처럼 보여주지 않는다.

### 인수 시험

T1에서 T2 약화→T2 포격 순으로 확정하면 T2 포격에 약화가 적용된다. T3 예약을 앞당기려는데 T2가 만석이면 명령 전체가 실패하고 AP와 모든 예약이 보존된다. 마지막 적 처치로 예약 해결이 중단되어도 남은 카드의 위치 기록은 유지한다.

## 08. 카드 조립: 자유도와 캐릭터 정체성

| 구성 | 규칙 | 예시 |
| --- | --- | --- |
| 고유 핵심 | 피해·방어·성장·계약의 대표 기능은 바꿀 수 없음. | 저격 포격을 광역 회복으로 변경하지 않음. |
| 시간 회로 1칸 | 즉시/지연/다중 전달 등 1개 선택. 강력할수록 비용 또는 기본 수치 대가. | 지연 증폭: 예약 시 기본 피해 +40%, 즉시 사용 시 -10%. |
| 보조 각인 1칸 | 관통·보호·회수 등. 동일 계열 중복 금지. | 관통: 대상 방어의 50%를 우회. 소멸 부여 각인은 별도 예산. |

### 개조 획득과 비용

기본 회로 6종은 튜토리얼·계정 성장으로 확정 해금한다. 추가 회로는 탐사 기록소에서 처음 발견하면 도감에 등록된다. 공방에서 해금된 일반 부품 제작은 연구편 10 + 크레딧 5,000, 희귀 부품은 연구편 30 + 크레딧 15,000. 첫 제작 후 해당 설계는 횟수 제한 없이 무료 교체한다.

영구 부품은 소모 장착품이 아니라 해금된 조립법이다. 탐사 중에는 현지 상점·공방에서 잔향 동전을 사용한다. 전투 중 임의 개조는 불가하며 니아의 고유 카드만 제한적으로 허용한다.

### 금지 조합

비용 0 + 자신을 손으로 복귀 + 행동력 생성처럼 닫힌 무한 자원 순환을 검출한다. 같은 효과를 여러 이름으로 우회하는 경우도 효과 태그로 검사한다. 모든 합법 조합의 설명·비용·실제 결과를 같은 데이터에서 생성한다.

## 09. 카드 풀과 보상의 구체적 구성

| 카드 예시 | 기본 효과 | 개조 방향 |
| --- | --- | --- |
| 세라 / 유리탄 | 1행동력, 단일 피해 10. 예약하면 14. | 관통 / 표식 집중. |
| 세라 / 정조준 | 1행동력, 다음 공격 기본 수치 +40%. 1턴 유지. | 예약 보조 / 빠른 연계. |
| 니아 / 약화 장치 | 1행동력, 다음 턴 대상 받는 피해 +25%, 그 턴 종료까지. | 2대상 분배 / 지속 감소 대신 강화. |
| 유리 / 유리 고치 | 1행동력, 방어 6. 예약 해결 시 성장 1. | 수호 진화 / 포식 진화. |
| 라비엔 / 선불 계약 | 0행동력, 지금 +2 / 다음 턴 -2. 전투 1회 소멸. | 상환 조건 변경, 총 차입 한도 유지. |
| 하린 / 경계 방패 | 1행동력, 방어 10. | 예약 아군 보호 / 즉시 반격. |
| 공통 / 정리 | 0행동력, 1장 버리고 1장 뽑음. 전투 2회 후 소멸. | 안정성 보완, 무한 순환 금지. |
| 공통 / 응급 수리 | 1행동력, 체력 5 회복. 전투 1회 소멸. | 방어 전환 / 디버프 정화. |

숫자는 표준 전투력 40·스킬 Lv.1 기준이다. 실제 피해·방어는 소유 캐릭터의 계산식으로 표시한다. 공통 카드는 파티 전투력 평균을 사용하고 출발 시 3장까지, 같은 공통 카드 최대 1장이다.

보상은 편성 캐릭터 카드 2개 + 공통/부품 1개를 기본 3택으로 제시한다. 캐릭터별 제시 횟수의 차이가 2회를 넘으면 가장 적게 제시된 캐릭터를 다음 보상에 포함한다. 선택하지 않고 잔향 동전 15를 받는 것도 가능하다.

> 출시 목표 10명 × 고유 카드 12종 = 120종, 공통 18종, 무기 카드 12종: 기본 카드 정의 총 150종. 개조 조합을 “수천 장의 카드”로 별도 집계하지 않는다.

## 10. 캐릭터 구성과 획득·해금

| 가안 캐릭터 | 운영과 약점 | 획득안 |
| --- | --- | --- |
| 세라 / 시간 저격 | 예약 폭발. 초반 대응과 다수 적 정리가 약함. | 상위 희귀도, 상시 선택권 대상. |
| 니아 / 기억 공학 | 전투 중 제한 개조. 직접 피해가 낮음. | 기본 지급 캐릭터. |
| 유리 / 공생 기록 | 성장·진화(E). 준비가 길고 즉시 폭발이 약함. | 상위 희귀도, 무료 체험 제공. |
| 라비엔 / 계약 중개 | 차입·상환(F). 무리한 사용 시 다음 턴 제약. | 상위 희귀도, 무료 체험 제공. |
| 하린 / 경계 수호 | 방어·반격. 방어 무시 적에 운영 변경 필요. | 기본 지급 캐릭터. |
| 리엔 / 잔향 연주 | 즉시 연쇄·보조. 높은 단발 화력이 약함. | 기본 지급 캐릭터. |
| 나머지 4명 | 회복 정화 / 덱 압축 / 표식 사냥 / 위험 전환. | 기본 희귀도 1명, 상위 희귀도 3명. |

출시 가안: 상위 희귀도 6명 + 기본 희귀도 4명. 기본 3인 파티와 상시 상위 1인 선택권을 초보자 과정에서 지급한다. 상위 캐릭터 중 1명이 최초 픽업 대상, 나머지 5명이 상시 풀이다. 선택권은 상시 풀만 대상으로 하며 이후 신규 한정을 소급 포함하지 않는다.

고유 카드 12종 중 대표·기초 6종은 획득 즉시 해금한다. 계정 공통 튜토리얼로 3종, 해당 캐릭터 개인 훈련 3개를 완료하면 나머지 3종을 해금한다. 모든 핵심 운영은 Lv.1에서도 작동하며 중복 획득으로 새 메커니즘을 잠그지 않는다.

상시 실험실에서는 미보유 캐릭터를 정해진 레벨·무기·부품으로 무제한 시험한다. 정규 보상 모드에 대여할 때는 기본 보상용 파티를 제공하고 점수 경쟁에서는 사용 여부를 구분한다.

## 11. E형: 살아 있는 카드의 성장과 진화

### 성장 규칙

유리 카드에는 카드 개체별 성장치 0~3이 있다. 성장 태그가 달린 카드가 예약으로 해결될 때 +1. 전투당 파티 전체 성장 획득 최대 3, 동일 개체는 전투당 +1까지만 허용한다. 성장치 3이면 전투 후 수호형/포식형 중 하나를 선택한다.

| 카드 개체 | 변화 | 대가 / 제한 |
| --- | --- | --- |
| 유리 고치 → 수호 | 기본 방어 6→9. 예약 해결 시 추가 방어 4. | 즉시 피해 능력 없음. |
| 유리 고치 → 포식 | 기본 피해 9. 이번 탐사 최초 처치 시 성장 각인 획득. | 방어 기능 제거. 각인 효과는 탐사당 1회 획득. |
| 공생 뿌리 → 보호망 | 다음 예약 1개에 취소 방지 적용. | 적 전체 시간 교란은 막지 못함. |
| 공생 뿌리 → 사냥망 | 표식 적 처치 시 다음 예약 피해 +20%. | 같은 턴 1회. 연쇄 처치로 무한 중첩 불가. |

### 탐사와 계정의 경계

진화한 카드와 성장치는 탐사 종료 시 사라진다. 발견한 진화 경로·대사·도감은 남는다. 설계도에는 “수호형 진화 우선” 같은 추천 분기만 저장하고 진화 완료 카드를 영구 시작 카드로 반입하지 않는다.

### 악용 방지와 UX

무해한 적을 남기고 수십 턴 버티는 성장 파밍을 차단한다. 이미 성장 제한에 도달하면 카드 옆에 “이번 전투 성장 완료”를 표시한다. 진화는 전투 중 강제 팝업이 아니라 보상 화면에서 선택하고, 실수 방지를 위해 변화 전후 효과를 나란히 보여준다.

> 애착은 카드 개체의 영구 능력치가 아니라 발견 기록·별칭·진화 도감으로 남긴다. 카드 별칭은 기기 표시용이며 다른 이용자에게 공유할 때는 기본 이름을 함께 표시한다.



### v0.6 저장 경계 보완

GrowthPoints와 진화 분기는 탐사 카드 인스턴스에 남기고, HasGrownThisBattle·전투 사용 횟수·파티 성장 횟수는 **전투마다 초기화**한다. 카드 정의 객체에는 상태를 기록하지 않는다. 성장 3 도달 뒤 진화는 전투 보상 화면에서 분기를 골라 적용하며 전투 중 몰래 성능을 바꾸지 않는다. 참조 엔진의 evolve(..., battle_finished=True)은 분기 데이터 전환의 P0 예시다. 모든 진화 카드·아트가 구현된 것은 아니다.

## 12. F형: 차입·상환·위약의 수치

| 계약 | 즉시 혜택 | 미래 비용 |
| --- | --- | --- |
| 선불 계약 | 0비용, 행동력 +2. 소멸. | 다음 턴 시작 행동력 -2. 전투당 1회. |
| 절제 계약 | 이번 턴 카드 3장 이하 사용 시 다음 예약 +30%. | 4장째부터 계약 파기. 다음 턴 첫 드로우 -1. |
| 담보 계약 | 예약 슬롯 1개를 봉인하고 방어 20. | 해당 슬롯은 다음 턴 종료까지 사용 불가. |
| 유예 협상 | 예정된 상환 1개를 1턴 미룸. | 상환 행동력 +1. 같은 상환에 재유예 불가. |

예약한 행동의 비용은 예약 확정 시 지불되므로 다음 턴 상환 때문에 이미 지불한 예약이 취소되지는 않는다. 단, 예약 효과 자체에 추가 지불 조건이 있다면 해결 전에 다시 확인한다.

### 부채 상한과 부족분 처리

행동력 부채 총량은 4를 넘을 수 없다. 넘기는 차입은 사용 불가이며 이유를 표시한다. 턴 시작 행동력 4를 회복한 뒤 부채를 우선 차감한다. 비용 감소로 상환을 무효화할 수 없고, 상환 면제 효과를 만들 경우 전투당 1회·특정 계약만 대상으로 제한한다.

전투가 끝나면 단기 전투 계약은 종료된다. 따라서 마지막 공격을 위한 차입은 합법적인 전략이다. 이를 악용으로 보고 보스를 강제로 살려두지 않는다. 탐사 전체에 영향을 주는 장기 계약은 별도 아이콘과 명시된 유지 기간이 있는 경우에만 이월한다.

### 사용 전 설명

확정 버튼 위에 “지금 행동력 2 획득 / 다음 턴 기본 4 → 2”처럼 실제 변화량을 표시한다. 비용 미리보기는 현재 계약과 장비를 반영한다. 위약은 알려진 전략적 대가이며 유료 계약 취소권·부채 삭제 상품은 판매하지 않는다.



### v0.6 계약의 정확한 시점

모든 F 계약은 즉시 사용이며 같은 행동을 예약해 부채 상한 검사를 피할 수 없다. 차입은 현재 AP+2가 9를 넘으면 확정 전 거절한다. 손해가 있는 자동 차입은 허용하지 않는다. 부채는 생성 ID·due_turn·amount·deferred로 저장하고 총합은 4 이하다.

절제 카드는 자신도 이번 턴 사용 장수에 포함한다. 턴 종료 시 3장 이하일 때만 **다음 턴의 첫 예약 피해·방어 효과에 +30%**를 부여한다. 다음 턴에 쓰지 않으면 만료한다. 4장째에는 한 번만 파기되어 다음 드로우 -1, 같은 턴 재계약으로 복구할 수 없다. 성장·드로우처럼 숫자 공격·방어가 아닌 예약에는 보너스를 소비하지 않는다.

담보는 빈 슬롯이 있을 때만 사용하며 다음 내 턴 종료까지 봉인한다. 유예는 다음 턴에 도래할 미유예 의무 하나를 선택하고 1턴 연장+금액 1을 함께 반영한다. 다음 턴에 임의의 다른 부채를 대신 유예하지 않는다. 단기 전투 차입 후 승리는 합법적 전략이고 영구 계정 빚을 남기지 않는다.

## 13. 맵 선택과 경로 생성

<!-- diagram:map -->

기본 탐사는 2개 구역, 구역당 7개 선택 지점으로 구성한다. 각 지점은 2~3개 선택지이고 한 경로에서 총 14개 노드를 방문한다. 첫 구역 마지막은 중간 보스+기록소, 둘째 구역 마지막은 최종 보스다. 목표 플레이 시간 15~25분은 실측 전 가설이다.

| 규칙 | 정의 |
| --- | --- |
| 공개 정보 | 현재 구역의 노드 종류와 보스 핵심 패턴은 공개. 사건 세부 결과는 진입 전 요약만 공개. |
| 안전 경로 | 첫 두 선택에서 엘리트 금지. 4~6번째 지점 중 회복/공방을 지나는 경로 최소 1개. |
| 위험 경로 | 엘리트는 구역당 최대 2회, 연속 배치 금지. 추가 유물·희귀 부품을 명시. |
| 연결 검증 | 모든 선택지에서 다음 노드와 보스에 도달 가능. 막다른 길·건너뛰기 비용 누락 검출. |
| 시드 | 탐사 시작 시 서버가 고정. 종료·재접속으로 상점·보상 재추첨 불가. |
| 보상 성향 | 출발 전 회로 / 방어 / 유물 실험 중 선택. 관련 보상의 제시 가중치 +25%, 확정 드롭 아님. |

> 맵 선택은 단지 쉬움/어려움이 아니다. 체력이 부족하면 회복, 덱이 무거우면 정리, 특정 콤보가 보이면 개조를 선택하게 한다. 유료로 경로를 다시 뽑거나 위험 정보를 더 보는 상품은 제외한다.

### 사건 예시: 멈춘 약속

선택 A: 최대 체력 10%를 잃고 희귀 각인 1개를 선택한다. 선택 B: 동전 40을 내고 일반 회로 1개를 선택한다. 선택 C: 아무 변화 없이 떠난다. 죽게 되는 체력 지불은 막고, 희귀 각인이 실제 후보로 존재하는지 사전에 검사한다.

계정 보상 재료는 노드별로 “미확정 가방”에 기록한다. 이 가방과 현지 동전은 별개다. 무한 무료 탐사는 도감 발견만 진행되고 성장 재료의 무한 공급처가 되지 않도록 보상 횟수·기간을 분리한다.

> 탐사 계정 보상은 주간 상한을 공유한다. 크레딧 50,000·연구편 30을 노드 가방으로 나누며, 패배로 일부만 회수했다면 남은 주간 한도까지 재도전할 수 있다. 계정·주차별 실제 지급 누적액에 한도를 적용한다. 탐사 활동 100점의 결정 200은 별도 1회 지급하며, 아래 재화표의 주간 탐사 총량에 이미 포함된다.

### 소멸하는 덱의 정확한 뜻

추가 카드·임시 강화·진화·유물로 만들어진 “이번 탐사 인스턴스”만 끝난다. 과거에 공방에 저장한 설계도를 삭제하지 않는다. 계정 성장 재화, 유료로 얻은 캐릭터, 영구 무기가 사라지는 것은 아니다.

### 탐사 보상과 비용

주간 기본 탐사에는 입장 체력을 받지 않는다. 주간 보상은 진행도 100점 1회이며 중간 보스까지 50점, 최종 보스까지 추가 50점. 패배 후 재도전으로 점수를 합산할 수 있지만 이미 받은 노드의 계정 재료는 같은 run_id로 중복 지급하지 않는다. 반복 탐사는 도감·설계 실험용이다.

> 상시 하드 및 별도 하드코어 모드는 출시 범위에서 제외한다. 난도 높은 경험과 추가 모집 보상은 주기 갱신 도전에 통합한다. 탐사에는 유료 부활·유료 보상 보험을 넣지 않는다.

가방의 50%·25% 회수는 수량형 일반 재료만 대상으로 한다. 고유 설계도 발견은 기록소에서만 계정에 확정하고, 미확정 고유 보상은 분수 환급하지 않는다. 반복 탐사에서 계정 재료는 주간 총량 한도를 함께 적용해 새 run_id로 무한 파밍하지 못하게 한다.

등급이 낮은 캐릭터도 동일 Lv.80 상한과 동일 스킬 상한을 가진다. 희귀도에 따라 덱 운영의 복잡성·연출을 다르게 할 수 있지만 레벨 상한을 막아 기본 파티를 강제 폐기하지 않는다.

| --- | --- | --- | --- |

제련핵은 주간 증표 60개로 주 2개, 42일 이벤트에서 3개를 확정 지급한다. 이벤트 D7·D22 지급분까지 포함하면 4주에 8+2=10개이므로 무기 하나를 R5로 완성할 수 있다. 중복 무기를 먹이는 방식이 아니라 계정 공통 제련핵을 사용한다.

### 교정 모드

무기 Lv.40에 A/B 모드를 선택할 수 있다. A는 예약 피해 보조, B는 즉시 피해 보조처럼 같은 총 성능 안에서 역할을 바꾼다. 전투·탐사 중에는 고정, 공방에서는 무료 변경. 유료 랜덤 옵션 재설정은 없다.

### 환급과 장비 갈아타기

같은 무기군의 다른 무기로 갈아타는 전승은 사용 경험치와 돌파 재료 100%를 이전하고 고정 크레딧 10,000을 소모한다. 제련은 전승 대상의 같은 R단계로 이전한다. 원래 무기는 Lv.1·R1이 되며 전승 전후를 확인한다. 인벤토리 합성으로 자원이 늘지 않도록 실제 지불 내역을 이동한다.

단순 해체는 경험치·돌파·제련 재료 80%, 사용 크레딧은 환급하지 않는다. 반올림 없이 내림. 기본 지급 무기는 해체 불가이며 재제작 가능한 무기도 잠금 해제와 2차 확인을 거친다. 전승이 해체보다 유리함을 UI에 명시한다.

> 이전 단계 가격에서 무기 제작비 50,000은 별도다. 기본 지급 무기에는 제작비가 없고, 성장 총액 표는 제작비를 포함하지 않는다. 무기를 여러 개 만들면 그만큼 제작 재료와 비용이 추가된다.

전승 대상은 같은 무기군의 Lv.1·R1·미돌파 무기만 가능하다. 이미 성장한 무기에는 덮어쓰기를 허용하지 않는다. 기존 무기의 성장 비용 원장은 새 무기로 옮기고 원래 항목을 0으로 만들어 전승 후 양쪽 해체로 중복 환급하지 못하게 한다.



주간 2회 교환은 계정 단위다. ‘4주’는 주간 초기화 4번과 D22 보상까지 확보한 정렬 예시이며 신규 계정의 정확한 달력 28일 보장은 아니다. 여러 무기에 제련핵을 분배하면 각 무기의 완성 시점은 늦어진다. 전승·해체는 DB의 동일 트랜잭션에서 소유권·장착 여부·원장을 잠근 후 처리하며 실패 시 10,000크레딧도 차감하지 않는다.

## 27. 장비 두 슬롯: 작은 성장과 명확한 유틸리티

첨부 제안의 투자 체감 문제는 받아들이지만 기초 체력과 갑주를 동시에 대폭 올리지는 않는다. **캐릭터 기초 HP=60+Lv 유지**. 장비 미장착은 null이며 +0 장착과 구분한다.

| 항목 | 갑주 | 장신구 |
| --- | --- | --- |
| +n 주 능력치 | 고정 HP 2+n, 비율 HP 3%+0.6%p×n | 피해·방어 효과 2.5%+0.5%p×n |
| +0 | 고정 2 + 비율 3% | 2.5% |
| +6 / +9 | 고정 8·6.6% / 고정 11·8.4% | 5.5% / 7.0% |
| +12 / +15 | 고정 14·10.2% / 고정 17·12% | 8.5% / 10.0% |
| +6 보조 | 정해진 3개 중 선택 1 | 정해진 3개 중 선택 1 |
| +12 세트 | 같은 캐릭터의 두 부위 모두 +12 이상·같은 세트 | 파티의 같은 세트 효과는 중복 발동하지 않음 |

n-1→n 비용은 연마재 2n + 크레딧 1,000n, 성공률 100%. 한 부위 +15는 240개·120,000, 두 부위는 480개·240,000. 강화 실패, 무작위 부옵션, 강화 재분배는 없다. 선택 보조 변경은 5,000크레딧, 미리보기는 무료다.

| +6 선택 옵션 | 정확한 범위 |
| --- | --- |
| 갑주 A: 준비된 방어 | 전투 시작 공유 방어 6. 파티 중복 시 1회만. |
| 갑주 B: 예약 회수 | 착용자 예약 카드 해결 시 HP 2 회복, 파티 턴당 최대 2. 치명 피해 판정 이후 실행 불가. |
| 갑주 C: 상태 보호 | 공유 파티의 지속 피해 15% 감소. 같은 옵션은 최고 수치만. 직접 공격에는 미적용. |
| 장신구 A: 예약 강화 | 착용자 예약 피해 +6%. 회로·무기·유물과 같은 가산 그룹. |
| 장신구 B: 즉시 강화 | 착용자 즉시 피해·방어 +5%. 일반 회복·AP에는 미적용. |
| 장신구 C: 공명 축적 | 착용자 필살기 충전량 +15%. 기본 10.0→11.5, 턴 30.0·총 100.0 상한 유지. |

시계공: 파티 첫 예약 피해/방어 +20%. 수호 기록: 시작 방어 8. 정원사: 첫 성장 또는 성장 캐릭터 미편성 시 세 번째 예약에 방어 5, 전투 1회. 공증인: 부채 상환 턴의 첫 공격 +10%, 미편성 시 3턴째 첫 공격. 같은 세트 중복은 소모 기회를 늘리지 않는다.

만렙 3인 체력은 미장착 420, +0 갑주 438, +15 갑주 **525**다. 기존 +15 468과 비교해 12.18% 늘지만 첨부의 1,419처럼 전투 스케일 전체를 바꾸지 않는다. 아직 실제 체감·승률이 확인된 수치는 아니다. 72절의 적 피해·회복 검증을 통과한 뒤 확정한다.

> 수식·예약 보조·게이지 관련 일부는 참조 엔진에서 검사했다. 위 모든 보조·세트·유물을 실제 게임에서 구현·플레이한 것은 아니다. 데이터에서 ‘미지원’ 효과를 로더가 조용히 무시하는 것을 금지한다.

## 28. 유물은 탐사 규칙을 바꾼다

유물은 계정에 장착하는 영구 장비가 아니다. 이번 탐사에서만 적용되는 규칙 변경이며, 희귀도는 등장 빈도와 복잡성을 나타낸다. 유물을 얻으면 도감의 발견 상태만 영구 저장한다.

| 유물 가안 | 효과 | 대가 / 안전장치 |
| --- | --- | --- |
| 빈 시계 | 첫 예약 비용 -1. | 전투 1회, 비용 최저 0. |
| 금 간 모래시계 | 다다음 턴 슬롯 +1. | 첫 턴 행동력 -1. 총 예약 최대 5칸. |
| 공방의 불씨 | 공방 노드에서 서비스 하나 추가. | 노드당 1회. 무한 제거 불가. |
| 기억의 봉투 | 이번 탐사 첫 치명 피해를 체력 1로 생존. | 즉시 소멸. 재획득·재충전 불가. |
| 미완성 악보 | 한 턴 3캐릭터 카드 해결 시 1장 드로우. | 턴 1회. 필살기는 카드 수에서 제외. |
| 공생 이끼 | E형 성장 발생 시 방어 3. | 전투 3회. 다른 캐릭터 조합에는 예약 3회마다 1회. |
| 외상 장부 | 다음 턴 부채가 있으면 이번 첫 공격 +20%. | 행동력 부채 상한 4는 변하지 않음. |
| 거절의 미덕 | 카드 보상 거절 시 최대 체력 2 증가. | 탐사 4회, 종료 시 원복. |

출시 목표는 일반 18·희귀 10·보스 4, 총 32종이다. 같은 유물 중복 획득은 허용하지 않고 같은 기능군이 중첩될 때의 우선순위를 명시한다. 보상 후보가 부족하면 무작위 재추첨 대신 같은 등급의 미보유 후보 전체에서 선택한다.

> 무기 = 캐릭터 운영 선택, 장비 = 작은 영구 보강, 유물 = 이번 판의 큰 변화. 세 시스템의 역할이 겹치면 유물 쪽에 새 규칙을 주고 영구 수치 증폭은 줄인다.

### 원문의 계산 오류와 수정

소유자 전투력40, 스킬1, 예약 기본14, 회로+40%, 무기+8%, 약화+25%에서 동일 그룹은 1.40×1.08이 아니라 **1+0.40+0.08=1.48**이다. 장신구 미장착 피해는 floor(14×1.48×1.25)=**25**. v0.4 본문의 26은 다른 그룹처럼 곱한 결과였다. 기존 +15 장신구4%면 26, v0.6 +15 장신구10%와 예약 보조6%면 floor(14×1.54×1.10×1.25)=**29**다.

### 관통의 의미를 고정한다

‘방어 50% 우회’를 남은 방어량의 절반으로 재해석하지 않는다. v0.6은 **최종 피해 중 관통 비율만 직접 HP에 적용**한다. 관통 피해=floor(피해×관통률), 나머지는 일반 방어로 막는다. 피해10·방어100·관통50%이면 HP5 감소·방어5 감소. 관통은 최대100%, 같은 적에게 중복 처리를 하지 않는다.

버전별 공식 ID와 콘텐츠 해시를 저장한다. 구버전 진행 전투에는 갑자기 새 수식을 끼우지 않는다. 동일 공개 상태의 계산은 재현 가능해야 하지만 C#·Python 완전 동치와 IL2CPP는 아직 실행 검증하지 않았다. [R01,R02]

## 31. 스토리와 캐릭터 상품의 연결

시간이 멈추거나 반복되는 도시에서 기억 공방을 운영한다. 카드는 기술·기억의 기록, 개조는 기록의 재구성, 예약은 미래 시점으로 보내는 동작이다. 유리의 생명 카드와 라비엔의 계약은 이 세계의 다른 이용 방식이다.

| 콘텐츠 | 초기 분량 가안 | 서사 원칙 |
| --- | --- | --- |
| 프롤로그 | 3전투·짧은 선택 2개·약 15분 목표 | 첫 전투 전에 설정 사전을 읽히지 않음. |
| 메인 1~3장 | 장당 6전투+4대화+보스 1. 첫 지역 사건 완결. | 위기 원인→인물 동기→선택→결과 순서. |
| 캐릭터 개인편 | 인당 6화×3~5분. 핵심 캐릭터부터 출시 품질. | 메인에서 빠진 필수 정보를 뒤늦게 보충하지 않음. |
| 공방 일상 | 인당 공통 대화 12·친밀 대화 6·상호반응 4 | 강한 전투 모습과 일상 약점의 대비. |
| 시즌 이벤트 | 42일에 완결 단편 1개·전투 6개·재활용 도전 | 종료 뒤 필수 스토리는 다시보기. 이벤트 보상은 소급하지 않음. |

세라: 미래 예측과 불완전한 과거. 니아: 타인의 기억은 고치지만 자신의 기억은 피함. 유리: 카드 속 생명을 동료로 봄. 라비엔: 약속에 엄격하지만 본인의 미해결 계약이 있음. 각자의 대표 카드 이름·음성·개인편에서 이 특성을 반복해 기억하게 한다.

> 플레이어는 외부 구원자를 기다리는 구경꾼이 아니라 복원 우선순위·위험 감수·협상을 결정하는 공방장이다. 주요 사건의 결과에 플레이어 선택의 영향이 남아야 한다.



### 이번 검토에서 추가한 제작 원칙

개인편 6화는 캐릭터 출시 시 텍스트 기준 완결성을 갖춘다. 나머지 절반을 복각까지 막아 이미 구매한 캐릭터의 서사 완성을 기다리게 하는 방식은 채택하지 않는다. 음성이 일부만 들어가는 경우 구매·도감에서 적용 범위를 사전에 표시한다. ‘부분 음성으로 제작비 30% 절약’이라는 수치는 근거가 없어 사용하지 않는다. 인력·총예산은 아직 사용자 확정값이 아니다.

**이 표는 달력 완료 예측이 아니다.** 28일 크레딧이 첫날 모두 지급되는 것도 아니며 42.5일 동안 추가로 생기는 무료 크레딧은 위 비교에서 다시 넣지 않았다. T3 해금 전 효율·시작 요일·이벤트·패스·성장 할인·플레이 누락도 실제 일정에 영향을 준다. 따라서 ‘1인 11일→6인 66일’도, 이 표의 ‘6인 89.92일 확정’도 주장하지 않는다.

승급핵은 주간3회×4=12개, 제련핵은 주간2+이벤트3/42일로 별도 제한된다. 스킬10의 추가비용은 교본168·크레딧600,000·완성핵12/캐릭터다. 무료패스·이벤트의 재료는 배정한 만큼 한 번만 공제하고, 여러 캐릭터 간 재화 경쟁을 기록한다. 77절에 달력 시뮬레이터 입력과 완료 기준을 명세했다.

## 41. 가챠 검산과 사업성은 서로 다른 검증이다

목표 픽업 확률 p=0.012, 픽업 확정 N=80, 픽업 외 SSR은 카운트를 초기화하지 않는 규칙이다. E[T]=(1-(1-p)^80)/p=**51.6103회**. 80번째까지 도달할 확률=(1-p)^79=**38.5300%**. 72회 안 획득은 **58.0724%**, 79회 안은61.4700%, 80회면100%다. 중앙값58회다.

최대 필요 결정 80×160=12,800. 제시된 반복 구매 팩 기준 최소 결제 조합은 3,440×3 +1,680+800=12,800, **165,000원**. 이는 기존 보유 결정·월정액·패스·최초 충전 보너스 없는 즉시 구매 비교이고 평균 필요 지출이나 모든 이용자의 비용이 아니다.

실제 가챠는 서버의 암호학적으로 적절한 난수원을 사용하고 계정별 천장·배너군·표 버전을 잠근 트랜잭션에서 1회씩 처리한다. 전투 재현용 ReplayRng는 가챠에 사용하지 않는다. 10회는 1회를 순서대로10번 처리하며80번째 픽업 보장 우선, 그 외 10회 SR이상 보장 규칙을 적용한다. 성공 결과·재화 차감·중복 조각·픽업 카운트가 한 번에 저장된 후 연출을 시작한다.

v0.6에서는 무료 재화를 임의로 줄이거나 중복 성능을 추가해 사업성을 ‘해결했다’고 하지 않는다. 기본 A는 무과금 접근성 가설, B는 축소 비교안이다. 실제 유료 출시는 비용 견적·상품별 구매 의향·부정적 경험을 따로 검증한 후 승인한다. 70~71절 참조. [R03,R07]

모든 의상에 360도 모델이 필요한 것은 아니다. 2D게임에서는 로비·전투·필살기·카드 탭의 실제 동영상/화면으로 확인한다. 보유하지 않은 캐릭터 의상은 구매 전 캐릭터미포함을 확인한다. 기간판매의 복각 여부와 최소 예상대기는판매시 고지하고, 나중에 영구판매를 예고없이 바꾸지 않는다.

### 무료 외형 보상

메인장 완료·호감도 30·기록 균열 성취·시즌 이벤트에서프로필·무기염색·기본급 의상 등을제공한다. 무료외형을 일부 남겨캐릭터 꾸미기가 과금메뉴에만 존재하지 않게 한다. 이벤트 의상의 추후 획득정책도 미리 명시한다.



### 중복 비주얼 제안의 처리

첨부의 중복1~3회 전용 로비 모션·컷인 해금은 기본안에 넣지 않는다. 전투 성능 차이가 없어도 캐릭터의 대표 상호작용을 확률 구매 뒤에 숨기면 체감 비용과 아트 제작량이 늘어난다. 기억 조각의 기존 교환처를 유지하고, 프리즘 프레임은 캐릭터 숙련 과제의 무료 외형 보상 후보로 검증한다. 추가 유료 카드 외형팩은 실제 구매 의향·기존 스킨과 중복 범위 확인 뒤 별도 SKU로 승인한다. 새 과금처가 확정된 것처럼 예산을 세우지 않는다.

### 터치 상태

`Idle → Focused → Preview → Pending → Applied`가 기본이다. 거절되면 Rejected 설명 후 Focused로, 응답을 잃으면 Reconciling으로 간다. 확정 전 뒤로가기·빈 공간·취소는 무료다. 확정 후에는 중복 클릭을 막고 같은 request_id로 결과를 조회한다. 서버 응답 전 후속 카드의 재화·손패 변경을 확정하지 않는다.

초기 기본은 카드 탭→대상/슬롯 탭→확정이다. 모든 행동에 영구적으로 3탭만 강제하지는 않는다. 이후 ‘즉시 사용 빠른 모드’는 사용성 시험을 통과한 사람 선택 옵션으로 검토하되 예약·위약은 확인을 유지한다. 드래그 단독 조작은 금지하지만 드래그 보조는 가능하다.

**고정1920×1080의 px 높이로 48dp를 보장할 수 없다.** 시제품은 CSS 48px 버튼의 경계와 동작만 자동 검사했다. 실제 Android dp/sp·Safe Area·글자 확대·손가락 가림은 Unity 실기기 P0 게이트다. 성장·부채는 위치를 고정하며 자동 호버로 타임라인이 접혔다 펼쳐지게 만들지 않는다. 73절에 시험 기준이 있다. [R04]

## 57. Unity·전투코어·계정서버의 경계

<!-- diagram:architecture -->

| 모듈 | 책임 |
| --- | --- |
| Unity클라이언트 | 카드 조작·미리보기·캐릭터 연출·UI·다운로드·입력. |

전투 행동은 서버가 승인하고 연출은 그 결과를 재생한다. 이미 알려진 숫자의 미리보기는 클라이언트 공용 코어로 계산하지만 미공개 드로우·적 랜덤값은 서버에 남긴다. 현금 재화와 모집의 난수는 전투·연출 난수와 분리한다.

> 이 문서는 아키텍처 설계와 작업 목록이며 실제 서버 프로젝트·Unity 씬·결제 SDK를 완성한 상태가 아니다. 생성한 저장소 인계 패키지도 기획·검산·규칙 파일 중심이다.



### 전달된 구현의 범위

Python 참조 엔진은 규칙 검증용이며 Unity에 직접 넣는 코드가 아니다. C# 커널은 .NET Standard2.1/C#8 대상으로 작성했지만 이 환경에서 dotnet·Unity 실행 도구가 없어 컴파일하지 못했다. 공식 Unity 지원 범위를 참고했을 뿐 실제 호환을 확인한 것은 아니다. 전투 전체 C# 포팅·서버 API·Unity 씬은 P0 작업표에 남겼다. [R01,R02]

## 58. 개발·검증·운영은 자산까지 분리한다

<!-- diagram:environments -->

| 환경 | 용도·접근 | 격리·데이터 |
| --- | --- | --- |
| local | 개발자PC·UnityEditor·로컬Docker | 합성 계정·가짜 결제·임시 DB. 인터넷 공개 불필요. |
| dev | Claude/Codex통합 결과·기능 검사 | 비운영 클라우드·VPN/접근 허용목록. 임의 초기화 가능. |
| staging | 출시후보·QA·Play시험 결제 | dev와 DB·키·계정 분리. 운영과 같은 구조, 합성 데이터만. |
| production | 실제이용자·실제 결제·자산 | 별도 클라우드 계정/프로젝트·네트워크·DB·KMS·백업. |
| preview(선택) | PR별임시API·프론트 | 합성 DB·자동 만료 24~72시간. 비용 상한 설정. |

dev와 staging은 초기에 같은 비운영 클라우드 계정에서 서로 다른 컨테이너·DB 사용자·DB·버킷으로 나눌 수 있다. production은 다른 계정/프로젝트를 기본으로 해 운영 권한을 가진 키가 개발 환경에 남지 않게 한다. DB 이름만 바꾼 같은 운영 관리자 접속 문자열은 분리로 보지 않는다.

각 환경은 API 주소·OAuth 대상·서명키·앱 식별자·DB·캐시 네임스페이스·CDN·푸시·로그·결제 검증 자격을 독립 설정한다. 운영 데이터를 테스트로 직접 복제하지 않고 개인정보 없는 합성 데이터를 쓴다. 개발 편의 재화 지급 명령은 운영 바이너리에 포함하지 않는다.



환경 식별자는 화면 색이 아니라 토큰의 issuer/audience, 패키지 ID, 구매 검증 자격 증명, DB 계정, 콘텐츠 서명키에 들어간다. dev와 staging도 서로 지갑을 공유하지 않는다. production은 별도 프로젝트·DB·객체 저장소·암호키를 권장하며 staging 데이터 갱신에 운영 개인정보를 통째로 복제하지 않는다. 결제 모의 승인기는 dev 전용 빌드에서만 컴파일·라우팅하고 production 설정에서는 시작 자체가 실패하도록 한다.

## 59. Play 테스트 트랙과 서버 환경은 별개다

| 항목 | 설계 |
| --- | --- |
| 개발앱ID | 예: com.example.memoryforge.dev. 가짜 결제만. example은 출시 전 실제 소유 네임스페이스로 변경. |
| 검증앱ID | 예: com.example.memoryforge.stg. 별도 Play 앱 등록·상품·시험 계정·staging 서버. |
| 실제앱ID | 예: com.example.memoryforge. 출시 패키지·서명키·production만 연결. |
| 시험 결제 | License tester와 테스트 결제 수단 사용. 테스트 트랙 자체가 무과금 설정은 아님. [S14] |
| 출시패키지검증 | 내부/비공개 트랙의 RC도 운영 패키지다. 일반 테스터 결제는 출시 전 비활성. 지정 시험 계정만 테스트 영역 사용. |
| 서버검증 | 패키지명·상품 ID·서명된 주문 상태·검증된 시험 구매 표시·계정 매핑 검사. 클라이언트 is_test값 신뢰 금지. |
| 경계차단 | staging 토큰/영수증은 prod 거부, prod 결제는 dev 지급 불가. 시험 재화는 운영 이전 없음. |

Google 공식 문서는 테스트 트랙의 일반 구매가 실제 청구될 수 있고 license tester의 시험 결제 수단을 권장한다고 설명한다. 패키지명이 Play 설정과 일치해야 한다는 조건도 있다. 따라서 “테스트 서버이니 결제는 자동 무료”라고 가정하지 않는다. [S14]

승인된 구매만 DB 단일 거래로 지급하고 purchaseToken 유일성 검사와 재처리를 지원한다. 보류 중 결제에는 지급하지 않고 환불·취소 통지를 반영한다. 네트워크 타임아웃은 재구매가 아니라 기존 주문 재조회로 복구한다. [S15]

> 출시 패키지의 테스트 구매를 점검할 때도 테스트 전용 계정·지갑 영역을 사용하고 일반 이용자 원장과 분리한다. “서버 환경 분리”와 “앱의 Play 배포 트랙”은 서로 다른 축이며, 앱 안에서 운영/개발 서버를 임의 전환하는 메뉴는 넣지 않는다.

## 60. 배포 승인·마이그레이션·롤백

<!-- diagram:deployment -->

| 단계 | 필수 통과조건 |
| --- | --- |
| PR검증 | 컴파일·전투 테스트·경제 합계·라이선스/시크릿 검사. 다른 AI의 교차 리뷰. |

DB는 expand → migrate → contract 순서로 새 필드를 추가하고 구버전과 동시 호환 기간을 둔다. 앱이 이미 사용자 기기에 배포됐으므로 서버만 이전 버전으로 돌려서 호환이 깨지지 않아야 한다. 파괴적 컬럼 삭제는 별도 승인과 백업 복구 연습 후 진행한다.

GitHub 환경 보호·필수 승인은 계정 플랜과 private 저장소 지원 범위를 확인해야 한다. 지원이 없으면 최소한 운영 클라우드의 수동 승인 경로로 분리한다. 워크플로에 approval이라는 문구만 있다고 실제 강제가 되는 것은 아니다. [S24]

먼저 작은 Unity 시험 프로젝트에서 카드 오브젝트 생성→프리팹 저장→플레이 모드→테스트→화면 캡처→Android 빌드를 수행한다. MCP가 Editor를 조작할 수 있다는 것과 게임 빌드·실기기 UX가 검증됐다는 것은 다르다.

> 이번 작업에서는 MCP를 사용자 컴퓨터에 설치하거나 Unity를 조작하지 않았다. 아래 인계 규칙과 체크리스트는 연결 후 개발할 때 적용할 설계다. API 토큰을 이 PDF나 레포에 넣지 않는다.



MCP 연결은 이번에 실행하지 않았다. CoplayDev unity-mcp는 제3자 도구이며 Unity 공식 제품이 아니다. 설치 시 저장소·커밋·라이선스·실행 권한을 검토하고 버전을 고정한다. Claude와 Codex가 동시에 같은 Unity Editor를 수정하지 않도록 단일 편집권을 둔다. 편집권은 계획상 파일 잠금만으로 보안 경계가 되는 것이 아니며 OS 권한·툴 허용 목록을 함께 적용한다. 외부 바인딩·운영 비밀·결제 키·운영 DB 쓰기는 허용하지 않는다. [R05,R06,R08]

## 71. BM 지속 가능성: 가격을 정한 뒤 확인할 비용과 구매 가설

월정액·패스·스킨 가격표는 유지한다. 다만 **가격표가 존재하는 것과 수익이 발생하는 것은 다르다.** 최소 월 운영비·캐릭터 제작비·고객지원·마케팅·외주비·예비비를 사용자가 실제 견적으로 채워야 한다.

### 입력을 숨기지 않는 민감도 분석

| 시나리오 | 월정액 구매 빈도/MAU·30일 | 유료 패스/MAU·42일 | 19,800원 스킨/MAU·42일 | 22,000원 충전/MAU·30일 |

800만원은 견적이 아니다. 사용자의 예산도 아니다. 300·800·1,500만원을 모두 파라미터로 넣은 결과가 ZIP에 있다. 단순 월 손익이며 초기 개발비 회수·CAC·LTV·시간에 따른 리텐션은 포함하지 않는다.

### 돈을 더 쓰게 만드는 대신 먼저 검증할 상품 가치

월정액: 적은 금액으로 예측 가능한 수집 진전, 누락 지급 자동 누적. 패스: 실제로 쓰이는 재료와 추가 모집, 없는 숙제를 만들지 않는 완주. 스킨: 로비·전투·카드·음성 중 어느 범위가 바뀌는지 명시. 대사·이야기를 인질로 삼는 미완성 상품이나 동일 외형 이중 구매는 제외한다.

상용 승인 전에 비과금 알파에서 좋아하는 캐릭터·체험 후 수집 의향·가격을 본 구매 의향을 조사한다. 그다음 정책·환불·결제 검증을 완료한 제한 판매에서 상품별 실제 구매·환불·민원을 확인한다. 통과 기준은 프로젝트 비용과 투자 한도에 맞춰 사람이 미리 승인하며, 근거 없이 ‘전환율5%면 합격’ 같은 보편 기준을 쓰지 않는다.

**실패 시 대안:** 캐릭터·음성 생산량 축소, 출시 지연, 유료 완결형+확장팩 구조 재검토 중 하나를 선택한다. 반복 수익이 증명되지 않은 상태에서 신캐·스킨 발행량을 늘리는 것으로 비용을 더 키우지 않는다.

## 72. 장비 리밸런싱 검증: 성장 체감과 적 스케일을 같이 본다

| Lv.80 3인·동일 갑주 | 미장착 | +0 | +15 |
| --- | --- | --- | --- |
| v0.4 | 420 | 432 | 468 |
| 첨부 v0.5 | 939 | 1,005 | **1,419** |
| v0.6 | 420 | 438 | **525** |

첨부의 (313+85)×1.19=473.62를 캐릭터별로 내림하면473이고,3인 합계1419다. 표시로 반올림한1420은 정수 판정과 다르다. 기존 +15 468 대비 약3.03배, v0.6의525는 기존 대비 약1.122배다. 크게 오른 HP 자체가 잘못은 아니지만 그 경우 모든 적 피해·회복·고정 방어·페이즈 길이를 함께 재설계해야 한다.

### +15가 무조건 정답이 되지 않게 하는 투자 단계

+6은 선택 유틸리티, +12는 세트, +15는 점진 수치 보강이다. +9의 비용은+15의37.5%(연마재90/240,크레딧45,000/120,000)다. 초반에는3인 전체 +6~9로 운영을 익히고, 일부를+12로 맞춘 뒤주력+15를 완성하는 계획을 안내한다. 모든 캐릭터+15를 스토리의 전제조건으로 잡지 않는다.

### 필요한 실플레이 비교군

같은 덱·적·시드에서 무장비 / +6 / +12 / +15, 즉시형 / 예약형 / E·F 혼합을 비교한다. 기록할 값은 승률만이 아니라 전투 턴수·받은 피해/최대HP·실제로 막은 방어량·회복 낭비·예약 사용 비율·장비 옵션 발동 횟수다. 레벨차가 장비 차이를 덮지 않도록 캐릭터·무기는 고정한다.

첫 보스는 원래 피해를 그대로 둔 비교와 새 목표 턴수에 맞춘 비교를 분리한다. 적 HP를 바꾸면서 장비를 강하게 만든 뒤 ‘새 장비가 재미있다’고 단정하지 않는다. 공격계수 변경과 회복 규칙 변경은 각각 ADR로 남긴다.

v0.6의 새 갑주와 장신구는 **검산한 제안**이지 실제 유저가 성장을 체감한 값이 아니다. 현재 자동 시험이 확인하는 것은525/29 등 수식과 적용 순서뿐이다. AI 전투 봇 하나의 승률을 사람의 재미로 대체하지 않는다.

P0 재현 RNG는 명시적 xorshift32+rejection sampling과 알고리즘 ID를 사용한다. 보안용이 아니므로 플레이어가 앞으로의 난수를 추측하면 안 되는 금전 가챠·권한 토큰에는 사용하지 않는다. 운영 가챠는 별도의 안전한 난수원·확률표 감사가 필요하다. [R03]

스냅샷은 서버에서 검증된 자료만 복원한다. 클라이언트가 제출한 임의 JSON을 restore()에 바로 넣지 않는다. 구버전 진행 세션을 지원할 기간과 종료 정책을 콘텐츠 배포에 포함한다. 형식이 맞지 않으면 기본값으로 덮어쓰지 않고 명시적으로 실패한다.

Python 참조는 저장→복원→같은 명령의 상태 해시 일치를 시험했다. C# 커널 RNG 알려진 값 비교 프로그램은 제공했지만 실행하지 못했다. cross-language JSON 직렬화·C# 전체 상태 해시·실제 DB원자성·프로세스 강제종료복구는 아직 통합 구현 과제다.

### 무한 루프 검증의 한계

정적 검사는 비용0·무한 자기복귀·AP생성처럼 알려진 금지 패턴과 부품 예산을 확인한다. 유한 사용 횟수 때문에 결국 끝나는 카드는 별도 취급한다. 여러 카드·유물·패시브가 섞인 모든 루프의 부재를 증명하지 않는다. 효과 그래프 검사·seeded fuzz·사람의 적대적 덱 설계·실행 이벤트 상한을 함께 써야 한다. 이벤트 상한 초과는 ‘플레이어 패배’가 아니라 버그 세션 격리·무소비 안전 중단으로 처리한다.

### 추천 배정 순서

첫 팀은 계정 해금 범위에서3인60·무기60·스킬6·장비+6~9를 우선한다. 그다음 주력1명의70/80·무기·스킬8을 보강하고 서포터는 필요한 임계까지만 올린다. 기록 균열 후반의 두 팀을 원할 때 두 번째팀을 키운다. 모든 캐릭터 종결 후 콘텐츠 시작이 아니라, 각 단계에서도 스토리·주간 보스·균열1~4에 참여할 수 있게 적 구간을 설계한다.

### 달력 모델의 구현 입력

향후 실제 계정 성장 시뮬레이터는 시작 UTC시각·서버 reset시각·계정레벨·T1/2/3해금·보유재료·목표인원·상품구매·일별접속·보상수령일·캐릭터별 우선순위를 입력으로 받아야 한다. day별 회복→상한 적용→보상 해금→원장 입금→선택 던전→성장 소모→주간제약 순으로 실행한다. 로그는 ‘누가 어떤 재료를 가져갔는지’를 남긴다.

현재 제공 스크립트는 T3 정규화 파밍량과 모집42일 지급 달력이다. **완전한 계정 레벨·모든 재료의 시간축 최적화 엔진은 아니다.** 그러므로 신규 유저의 종결 날짜를 확정적으로 말하지 않는다. 추격 성장 할인은 실제 지급 원장에 할인 후 비용을 기록해야 해체로 할인 전 재화를 받지 않는다.

### 주간 보스 횟수의 API 정의

입장·실패·연습은 claim 수를 쓰지 않는다. 승리한 run_id에 대해 수령 요청 시 account_id/week_id를 잠그고 기존 run보상 수령 여부→사용3미만→보상정의버전→재료원장을 한 거래로 반영한다. 마지막 수령 동시 요청 두 개는 하나만 성공해야 한다. 주간초기화는 클라이언트 시계가 아니라 서버 캘린더 키를 사용한다.

Play의 internal/closed/open/production은 **배포 트랙**이며 환경명과 자동으로 같지 않다. 같은 applicationId의 테스트 빌드라도 잘못된 서버를 바라볼 수 있다. 빌드의 package/env/API audience/content key/product catalog를 조합 검증하고, prod 서버는 dev issuer·mockreceipt를 거절한다. 테스트 구매가 무조건 무료라는 가정도 금지한다. [R10]

### 결제 검증의 최소 원장

클라이언트는 purchaseToken을 인증된 백엔드로 제출한다. 서버는 공식 API에서 package·상품·수량·구매상태·계정연결을 확인하고, 이미 처리한 토큰은 같은 지급 결과만 반환한다. PENDING은 지급하지 않는다. 검증→원장지급→ack/consume 재시도 작업의 상태를 나누되 중복 지급하지 않는다. 주문번호만을 유일키로 삼지 않는다. [R07]

유료/무료 결정은 분리잔액+이벤트원장으로 관리하고, 사용순서·환불취소·음수조정 정책을 사전 명세한다. 실제 결제 토큰은 공개 로그·AI 프롬프트·Git에 넣지 않는다. 환불 악용 조사와 정상 고객지원의 권한을 분리한다.

### 콘텐츠 변경과 마이그레이션

card_definition_version, rules_version, economy_version, catalog_version을 분리한다. 진행 탐사에는 시작 때 고정한 규칙을 사용하고 신규 시작에만 새 버전을 적용하는 기본안을 둔다. 치명 버그로 구버전을 중단할 때는 확정보상 보존·임시소비 환급·공지·이벤트원장 원인을 기록한다. DB 컬럼 삭제는 추가→병행읽기→전환→구버전중단→삭제 순서로 배포하고 백업복구 시험 전 운영마이그레이션은 금지한다.

### 백업과 복구

자동백업 성공문구만 확인하지 말고 staging의 폐기 가능한 DB에 복구해 소유목록·지갑원장합·모집천장·완료run의유일성을 검사한다. RPO/RTO는 사업허용손실과 복구실측으로 승인한다. 비상운영은 모집·결제일시정지·콘텐츠시작정지·읽기전용 전환을 각각 분리해 불필요한 전면폐쇄를 줄인다.

여기 명세와 server/schema.sql은 설계자료다. 실제 PostgreSQL동시성·결제API·재해복구를 이번 작업에서 시험하지 않았다.

### 파일의 상태 구분

EXECUTABLE_REFERENCE는Python P0엔진이다. SOURCE_NOT_COMPILED는C#커널이다. INTERACTIVE_MOCK은HTML이다. DESIGN_ONLY는API·SQL·환경·MCP절차다. MEASURED는로그에실제실행한결과,PROPOSED는게임수치·가격·공수목표다. 이범주를README·보고서·AI완료보고에서동일하게유지한다.

이패키지에는완성된Android게임·AAB·상용서버·실제캐릭터아트·음성·폰트파일이없다. 외부제안의좋은아이디어를보존하되검증되지않은코드를완성품으로취급하지않도록구성했다. 새기능을늘리기전에P0실기기와규칙연결을완성하는것이다음단계다.

C# 커널은 숫자·예약·계약 등의 포팅 시작점이다. .NET Standard2.1 대상의 실제 빌드가 끝나기 전 Unity 프로젝트의 공용 DLL로 배포하지 않는다. 모든 컬렉션·콘텐츠 상태를 외부 수정 가능한 참조로 노출하지 않도록 전체 엔진 포팅에서 경계를 유지한다.
