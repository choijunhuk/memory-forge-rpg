# 기억 공방 v0.8.1 — Claude·Codex 시작 프롬프트

이 파일은 v0.8.1 전체 설계서·개발 패키지와 함께 쓰는 **시작 지시문**이다. 설계서나 실행 코드를 교체하는 새 버전이 아니다. 원본 PDF·ZIP은 수정하지 않았다.

## 1. 전달 순서

1. 먼저 Codex에 `Memory_Forge_v0.8.1_Full_Handoff.zip`과 전체 PDF를 제공하거나, ZIP을 푼 `memory-forge-rpg` 프로젝트를 연다. `START_CODEX_MESSAGE.txt`의 **본문 전체**를 첫 메시지로 넣는다. 현재 환경에서 ZIP·파일 접근이 안 되면 그 제한부터 확인한다.
2. Codex가 실제 루트·기준 커밋·담당 분리를 확인한 뒤 Claude를 같은 저장소의 별도 worktree/브랜치에서 시작한다. `START_CLAUDE_MESSAGE.txt` 전체를 첫 메시지로 넣는다. 패키지 이름만 보내고 파일을 읽었다고 가정하지 않는다.
3. 두 작업 공간은 별도의 디렉터리다. 상대의 변경은 승인된 커밋·PR·패치로 받아야 보인다. 단순히 파일을 작성했다고 자동 전달되거나 상대 에이전트가 실행되는 것은 아니다. 대규모 자동 오케스트레이션부터 만들지 않고, 우선 Git 기반 인계로 시작한다.
4. 다음 세션은 `RESUME_MESSAGE.txt`를 사용한다. 새 ZIP을 계속 덮어풀지 말고 저장소의 현재 상태를 기준으로 이어간다.

최신 ZIP 안의 실제 시작 안내는 `docs/START_CODEX.md`, `docs/START_CLAUDE.md`다. 이 사용자 시작 메시지는 그 안내를 버리지 않고 **이미지 생성 담당과 협업 조건을 추가**하도록 작성했다.

## 2. 이번에 확정한 담당

| 작업 | 기본 담당 |
|---|---|
| 전투 규칙·저장·C# 이식·서버·검증 자동화 | Codex |
| UI/UX·서사·콘텐츠·아트 브리프·리소스 적용 | Claude |
| **그림 생성·재생성·이미지 내용 수정** | **Codex — 사용자의 별도 변경 지시 전까지 고정** |
| 결과 검토 | 작성자가 아닌 쪽의 교차 검토 + 주요 기준에 대한 사용자 판단 |

이 역할표는 본 프로젝트의 운영 지시이며 두 제품의 모든 기능·성능을 비교한 결론이 아니다. Codex 담당이라는 것은 해당 Codex 환경의 실제 이미지 생성 기능/스킬을 사용한다는 뜻이다. 모든 클라이언트에 특정 도구가 활성화됐거나 구독만으로 모든 호출이 무제한·무료라는 뜻이 아니다. 기능·권한·추가 과금은 세션 시작 때 확인한다.

```text
[검증과 보고]
문서 원본은 docs/source_v0.8.1이다. npm run docs 및 npm run test:docs로 최신 문서와 누락을 확인한다. 변경에 해당하는 코드·UI 시험은 직접 실행하며 미실행은 NOT_RUN, 실패는 FAIL로 기록한다. 테스트 통과를 위해 기준을 낮추지 않는다.
기획 설명만 반복하지 말고 실제 첫 UI 작업과 Codex용 이미지 요청부터 진행한다. 응답은 완료·검증·막힌 점·다음 작업만 짧게, 상세 내용은 변경 파일·스크린샷·인계 문서로 남긴다. 현재 세션 밖에서 자동으로 작업이 계속된다고 약속하지 않는다.
```

## 5. 저장소에 지속적으로 남길 공통 규칙

Codex가 초기 설정 때 기존 규칙을 삭제하지 않고 다음 내용을 AGENTS.md와 현재 결정 기록에 추가한다. CLAUDE.md·두 시작 문서는 동일한 기준을 가리키도록 정리한다. 이 파일 자체가 도구 권한이나 모델의 안전 기준을 변경하는 것은 아니다.

```text
이미지 생성 담당: Codex.
사용자가 별도로 변경을 지시하기 전에는 담당이나 생성 서비스 경로를 자동 변경하지 않는다.
Claude는 아트 기획·제작 요청·검수·리소스 적용을 맡는다.
Codex 이미지 도구가 없으면 해당 자산을 BLOCKED로 기록하고 필요한 조치를 보고한다.
Claude·타 이미지 서비스·로컬 모델·새 유료 API를 우회 대체재로 임의 사용하지 않는다.
비용·계정·API 키·외부 서비스 추가가 필요한 경우 사용자 확인을 받는다.
원본 그림을 보존하는 비생성형 리사이즈·압축·슬라이스·Unity 임포트 설정은 리소스 적용 담당이 수행할 수 있다.
확정된 디자인 시트·캐릭터 설정·사용자 결정은 유지한다. 수정은 변경 사유와 전후 결과를 기록한다.
```

## 6. 이미지 요청 인계 템플릿

아래는 **새로 만들 인계 양식**이다. 원본 ZIP에 이 큐가 구현되어 있다는 뜻은 아니다. `art/requests/` 아래 작업별 파일로 만들고, 서로 다른 worktree에서는 커밋/PR을 통해 전달한다. 사람이 눈으로 확인해야 하는 시트 승인 단계와 일상적인 반복 제작 단계도 구분한다.

```yaml
request_id: ART-SERA-SHEET-001
requested_by: Claude
generation_owner: Codex
status: ready_for_generation
subject_id: sera
asset_type: design_sheet
source_sections: [ch9, ch15]
source_prompt_file: art/briefs/prompts_v0.8.1.json
reference_files: [] # 실제 파일이 있을 때만 경로와 해시 기입
is_new_design_sheet: true
must_preserve: # 문서에서 읽은 현재 외형·설정·색·소품을 기입
requested_variation: # 표정/포즈/의상 세부 등 이번 요청만 기입
composition: # 시트/키아트/카드의 목적에 맞게 구분
output_spec: # 실제 문서의 해상도·비율·투명 배경·안전 영역 기입
output_directory: art/generated/sera/sheet/
acceptance_checks: # 얼굴·의상·무기 일관성, 읽기 쉬운 실루엣 등
review_owner: Claude
reference_approval_required: true
```

상태 예시: `draft → ready_for_generation → generating → generated → needs_revision/reviewed → integrated`. 막히면 `blocked`. 사용자 시트 승인이 필요하면 `awaiting_reference_approval`. 이미지 생성 완료와 게임 연결 완료를 같은 상태로 합치지 않는다.

생성물이 평면 PNG라면 평면 PNG라고 보고한다. 레이어 PSD, 투명 알파, Spine/Live2D 리그, 애니메이션이 실제로 생성되지 않았는데 파일 확장자나 목업만으로 완료라고 표시하지 않는다. 사용한 도구가 요청 규격을 직접 지원하지 않으면 가능한 출력과 필요한 후처리를 기록한다.

## 7. 기준선 검사 순서

아래 명령은 최신 package.json·README에서 확인한 진입점이다. 실제 프로젝트 루트에서 실행한다. 필요한 의존성은 설치된 버전과 패키지 지침을 확인하고 준비한다. 입력 무결성은 파일을 수정하기 전에 검사한다.

```sh
npm run verify:manifest
npm test
npm run test:proposals
python3 -m unittest discover -s tests -v
npm run test:docs
```

입력 검증 후 새 지시문·코드·로그를 작성하면 원래 출고 체크섬과 달라지는 것이 정상이다. 변경을 숨기지 않고 diff와 새 로그를 보존하며, 재배포할 때 원래 매니페스트를 이력으로 보존한 뒤 새 매니페스트를 만든다. 기존 입력을 재검증하기 위해 무작정 새 체크섬부터 만드는 방식은 쓰지 않는다.

현재 JS 참조가 통과해도 전체 C#·서버·Unity가 완성됐다는 뜻은 아니다. 저장 v2는 독립 모듈만 있으므로 실제 탐사/HTML 연결과 서버·이관·C#의 완료 상태를 각각 관리한다. 테스트 개수는 고정된 품질 점수가 아니라 이전 실행 이력이다.

## 8. 새 세션에서 이어가기

```text
기억 공방 개발을 이어서 진행해 줘. 현재 저장소의 AGENTS.md, CLAUDE.md(해당 시), docs/CURRENT.md, 최신 승인 결정, 마지막 인계 기록, 현재 브랜치·커밋·미커밋 변경을 먼저 확인해라. 기록과 실제 파일이 일치하는지 확인한 뒤 마지막으로 완료하지 못한 작업부터 이어간다. 기존 작업을 초기화하거나 ZIP을 다시 덮어풀지 마라.

기술 분업은 기존 담당을 따르고, 이미지 생성·수정은 별도 사용자 변경 지시가 없는 한 계속 Codex 담당이다. Claude는 요청·검수·게임 적용을 맡는다. 이미지 기능이 막혔다고 다른 공급자로 자동 전환하지 않는다.

과거 실행 보고를 새 PASS로 바꾸지 말고, 이번 변경에 해당하는 검사를 실행해라. 의존성이 풀린 작업은 자율적으로 진행하되 미결정 정책을 확정된 것으로 취급하지 않는다. 현재 세션에서 한 작업과 남은 작업을 짧게 보고하고 상세 로그·커밋·다음 작업을 인계 파일에 남겨라.
```

## 9. 한 번의 작업을 끝낼 때

최종 채팅은 다음 네 항목을 각각 한두 문장으로 보고한다. 상세 내용은 저장소에 남긴다.

```text
완료: 실제로 바꾼 것과 결과 파일/커밋.
검증: 실행 명령·결과·로그 위치. 미실행은 NOT_RUN.
막힌 점: 도구 부재·권한·사용자 결정 등 구체적인 사유.
다음 작업: 이어갈 작업 ID·담당·필요한 인계 파일.
```

인계 파일에는 기준 커밋, 작업 브랜치, 변경 파일, 실행 환경, 결정/질문, 생성 이미지 위치, 다음 작업, Unity 편집권 해제 여부를 남긴다. 새 에이전트는 이를 실제 파일·git 상태와 대조한다. 작업 목록이 많다는 이유로 기존 기능·문서·수치를 삭제해 완료 범위를 줄이지 않는다.
