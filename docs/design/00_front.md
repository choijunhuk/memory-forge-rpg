# 기억 공방 / Memory Forge — v0.7 통합 설계서

게임 명세 · 데이터 · 실행 가능한 규칙 참조 · 서버 계약 · 아트 지침 · AI 제작 계획

- 문서 버전: v0.7.0 · 작성일 2026-10-14 · 기준 규칙: `data/game_data.json` (rules 0.7.0)
- 이전 판: v0.6(2026-10-14, `docs/archive/design_v0.6.md`). v0.6 평가에서 나온 수정 사항은 §21에 모두 정리했다.
- 상태: **제작 착수용 기준선**. 사람 플레이 테스트·사업성·실기기 검증은 아직 하지 않았다(§0.4 표 참고).

## 0.1 이 문서를 쓰는 법

**사람(기획·아트·사업)** 은 §1 요약 → §2 콘셉트 → §3 루프 → 관심 있는 장 순서로 읽는다.

**AI 에이전트(Codex · Claude 등)** 는 다음 순서를 지킨다.

1. 저장소 루트의 `AGENTS.md`(공통 규칙)와 이 장의 §0.2 권위 순서, §0.4 구현 상태표를 먼저 읽는다.
2. 맡은 작업의 장을 읽고, 그 장이 가리키는 **데이터 파일과 테스트**를 연다. 수치는 문서 본문보다 데이터가 우선한다.
3. §20(단계별 제작 계획)의 해당 단계 "완료 조건"을 그대로 인수 시험으로 쓴다.
4. 규칙이 문서와 코드에서 다르면 임의로 고르지 말고 `docs/decisions.md`에 질문/ADR 초안을 남긴다.

## 0.2 권위 순서

| 순위 | 출처 | 설명 |
|---|---|---|
| 1 | 사용자(디렉터) 승인 | 대화·회의에서 확정한 결정 |
| 2 | `docs/decisions.md` | ADR 형식의 확정 결정과 채택하지 않은 제안 |
| 3 | 이 문서의 규칙 서술 | 전투 순서, 저장 규칙, 서버 계약 등 |
| 4 | `content/*.mjs` → `data/game_data.json` | 모든 수치·카드·적·확률. 이 문서의 표 대부분은 이 데이터에서 **자동 생성**된다(§0.3) |
| 5 | `engine/rules-core.js` | 실행 가능한 규칙 참조. 3·4와 다르면 버그로 본다 |
| 6 | `core/` C# · `server/` · `prototype/` | 이식·구현. 5와 같은 결과를 내야 한다(교차 벡터로 검사) |

## 0.3 자동 생성 표

`node tools/gen_docs.mjs`가 데이터·엔진·경제 검산 결과에서 다음 표를 만든다: 로스터·캐릭터 시트(§9.2·§9.3), 상태·키워드(§5.8), 효과 DSL(§6.3), 카드 수치 예산(§6.4), 부품(§6.6), 공용 카드(§6.7), 사건(§7.7), 유물(§7.8), 무기(§10.1), 적·조우(§10.2), 성장·비용(§11), 모집 확률·기대값·수급·상품(§12), 이미지 프롬프트(§15.6), 오류 코드(§23.2), 레벨 표(§23.3). 표를 고치려면 **데이터를 고치고 다시 생성**한다. 생성기는 데이터에 쓰인 효과 op·조건·카운터·오류 코드가 문서에 빠져 있으면 실패한다.

## 0.5 표기 규칙

- 확률·보너스는 bps(1bps = 0.01%)로 저장하고 %로 표시한다. 10000bps = 100%.
- "기준 전투"는 전투력 40(power4 160)·캐릭터당 체력 81·스킬 Lv.1 상태를 말한다. 카드에 적힌 수치는 기준 전투 값이다.
- "다음 턴"은 현재 턴 + 1, "다다음 턴"은 + 2. 예약은 **절대 턴 번호**로 저장한다.
- 카드·캐릭터·적 ID는 `코드체`로 쓴다(예: `sera_round`).
