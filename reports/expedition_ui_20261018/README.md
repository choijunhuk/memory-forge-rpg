# 탐사 연습 화면 UI/UX 재설계 (2026-10-18)

브랜치 `claude/expedition-ui-40eff0`. 루트 `codex/late-actions-balance`(305289b, 로비 포함)를 앞당겨 받은 위에서 작업했다. 시각 입력은 Codex 1차안 `art/candidates/20261018/codex`(design-spec.md, layout.json, previews)다. 레이아웃·상호작용은 이 세션이 정했고, 그림은 Codex 원본을 바이트 그대로 썼다.

## 바뀐 것

### 공통
- **장소 그림 + 남색 스크림.** 전투는 광장(`bg_zone1_battle` = `bg_zone1_battle_street_v02`), 지도는 시계탑 도시(새 사본 `bg_zone1_map` = `bg_zone1_map_clockcity_v02`), 나머지(보상·휴식·공방·상점·사건·기록소·저장·결과)는 공방 그림을 배경으로 쓴다. 공방 그림은 분위기 배경이고, 실제 장소는 화면 제목이 말한다. 2구역 전투도 지금은 같은 광장 그림이다.
- **글자는 모두 불투명 둥근 패널 위.** 절차 생성 9-slice 모서리(반경 14px) 하나로 모든 패널·버튼을 그린다. 테두리는 패널의 자식 `Edge`(고리 스프라이트)다. Outline 효과는 반투명 패널 뒤로 테두리 색을 비치게 해서 쓰지 않았다.
- **글꼴.** Regular 한 벌만 있으므로 굵게는 22pt 이상에서만 쓴다(작은 글자의 합성 굵기가 번진다).
- **긴 글은 자르지 않는다.** 규칙 글(적 이름·의도·상태·약점, 카드 효과, 보상·유물·부품·상점·사건 글, 기억 목록)은 `Grow`/`TextHeight`로 칸 높이를 정한다.
  - 실제 글꼴, 그 글이 그려지는 캔버스 배율, 3% 좁은 폭으로 잰다.
  - 줄바꿈은 배율을 따라 바뀐다. 그래서 캔버스 배율이 바뀌면(창 크기, 다른 화면, 카메라) 화면을 다시 그려 다시 잰다. 같은 화면을 다시 그릴 때는 측정값을 재사용한다.
  - 칸에 다 안 들어가면 그 칸만 스크롤한다.
- **이름 계약 유지.** `ExpeditionFrame`, `Enemy:<uid>`, `Party`/`Ult:<id>`, `Hand`/`Hand:<uid>`, `Node:<id>`, `EndTurn`, `Mode:now|next|after`, `ConfirmCard`, `Pace:*`, `Timeline`/`ReservationSlot`(첫 글자 칸 = 기존 문구), "파티 체력" 글자, `RewardCards`/`RewardCard:*`, `SkipCard`, `CardInfo:*`, `Proceed`, `Memory:*`, `CommitMemory`, `CloseWithoutSave`, 안내 대상 전부. 버튼 문구도 그대로다.
- **입력.** 버튼 하나에 맞는 칸은 하나다. 그림·장식·숫자는 레이캐스트를 받지 않는다. 카드 정보/확정과 대기 취소/카드 정보의 자리 바꿈, 턴 종료 아래쪽과 `Proceed`·`CloseWithoutSave`의 겹침, 마지막 행동 시트의 건너뛰기 자리 등 반복 탭 안전 배치를 유지했다.
- **`MemoryForgeUiSkin.cs` 삭제.** 배경·적 그림·파티 SD·피격 흔들림/번쩍임·누름/호버·화면 페이드를 클라이언트가 직접 그린다. 이름으로 찾아 덧그리던 스킨을 남기면 이중으로 꾸며진다.

### 전투
- 상단: 파티 체력 막대, 턴·방어·반격·부채·잔향, 뽑을/버림/소멸·동전, 파티 상태, **행동력** 칩.
- 파티: 동료마다 한 열(승인된 SD, 이름, 속성·게이지 숫자와 막대, `Ult:<id>`). 준비된 필살기는 황동 + 숨쉬는 빛.
- 적: Core 순서대로 무대 위에 배치. 정의 id로 그림을 찾는다(`enemy_<Id>`). 1~3명은 그림 옆에, 4~5명은 그림 위에 정보 패널이 온다. 패널은 이름, 체력/방어, 체력 막대, 균열 숫자 + 칸, 약점 낱말(넓은 칸은 Codex 속성 아이콘도), 상태, 기존 문구 그대로의 "이번/다음" 의도 상자. 모든 적 칸은 폭이 같다. 처치된 적도 제 칸에 흐린 그림·이름·체력 0·처치를 남기므로, 처치가 나도 살아 있는 적의 칸은 움직이지 않는다(소환으로 적이 늘 때만 다시 배치). 196보다 좁아지면 적 띠가 가로로 스크롤된다. 대상 선택 중에는 모서리 괄호가, 선택된 적에는 청록 테두리·괄호·"선택"이 붙는다. 엘리트·보스는 Core의 tier로 표시하고, 이 표와 "선택"은 이름 줄에 자리를 따로 잡아 이름을 가리지 않는다.
- 시간표: 칸마다 다음/다다음 글자, 카드 칸은 청록, 빈 칸·봉인·없음 구분, 다음 n/m · 다다음 n/m 사용량. 넘치면 가로 스크롤.
- 손패: 주인 컷인 띠(장식, 카드 효과를 묘사하지 않음; 컷인 없는 동료는 SD 얼굴, 공용·저주·무기는 무늬 없는 띠), 행동력 알약, 이름, **Core `BattleText.Card` 전체 효과**, 방식 표시(기존 "즉시 사용/즉시 · 예약/예약 전용"). 효과가 184폭에 안 들어가면 236/300으로 넓히고, 그래도 안 되면 자르지 않고 '카드 설명'을 가리킨다. Core가 행동력 부족(AP_LOW)이라 하면 알약이 회색이 된다. 선택된 카드는 올라오고 청록 테두리 + "선택".
- 방식 버튼: 즉시는 황동 테두리, 다음/다다음은 청록 테두리. 확정은 준비됐을 때만 황동. 턴 종료는 오른쪽 아래에 따로, 행동력이 0이면 숨쉬는 빛.

### 지도

### 보상·장소·저장·결과
- 보상: 동전 머리띠, 진화, 카드 3장(주인 띠, 이름, 카탈로그 줄, 전체 효과; 가장 긴 효과에 맞춰 높이), 별도 '카드 설명 보기', 받지 않기(동전 +15), 유물(전체 글), 부품. `Proceed`는 오른쪽 아래 고정.
- 휴식·공방·상점·사건·기록소: 왼쪽 장소 카드(Codex 아이콘, 제목, 소개)와 오른쪽 행 목록. 행은 글 길이만큼 자란다. 상점은 그룹별 타일(카드 3열, 부품·유물 2열)로 스크롤 없이 들어가고, 읽기와 사기는 다른 버튼이다. 카드 제거는 장소 카드에 항상 보인다.
- 저장: 규칙 머리띠, 캐릭터별 장부(초상, 출발 전 → 결과 용량, 넘칠 때만 위험색 + "용량 초과", 유지 덱, 고를 변화, 결과 미리보기, 빠지는 카드). 목록은 각자 스크롤. 저장 가능 여부는 Core 미리보기 그대로다.
- 결과: 통계, 저장 결과, 동료별 초상과 덱 목록(스크롤).

### 움직임 (`MemoryForgeUiMotion.Reduced` 또는 이 연습의 "동작 줄이기"면 모두 즉시)
- 화면 종류가 바뀔 때 페이드, 새로 열린 시트 페이드.
- 움직이는 도중에 "동작 줄이기"를 켜면 모든 움직임이 그 자리에서 끝 상태로 멈춘다(매 프레임 확인).
- 전투: 마지막으로 가려지지 않은 화면과 지금의 **공개 상태 차이**만 본다. 적이 맞으면 숫자가 떠오르고 그림이 흔들리며 붉게 물들고 체력 막대의 잃은 부분이 빠진다. 파티가 맞으면 파티 체력 줄(누를 것 없음)이 번쩍이고 막대가 빠진다. 회복·방어 증가는 숫자로. 새 손패는 펼쳐지듯 들어오고, 확정된 카드·필살기는 유령 카드가 대상(적)·시간표(예약)·파티로 날아간다. 유령은 모든 패널·버튼 아래(무대 스크림 바로 위)에 그려져 쓸 수 있는 버튼 글자를 가리지 않는다. 턴 요약이나 마지막 행동 시트가 덮고 있는 동안에는 비교하지 않고, 닫힌 뒤 한 번에 보여 준다.
- 움직이는 것은 그림(`Art`), 카드 앞면(`Face`), 숫자·유령뿐이다. 버튼의 맞는 칸은 움직이지 않는다. 거절된 명령에는 아무것도 날아가지 않는다(확정된 play/ult 뒤에만 비행).

## 휴대폰 가독성·터치 크기 (48dp)

1600×900 기준 화면을 안전 영역에 비율 유지로 맞춘다. 2340×1080에서는 양옆 띠를 배경색으로 채운다(위 표 마지막 줄).

**48dp는 실제 기기 밀도로 계산한다.** 휴대폰(`Application.isMobilePlatform`, dpi 확인 가능)에서 `minTouch = 48 × dpi / 160 ÷ (프레임 1단위당 화면 픽셀)`이다. 2340×1080·420dpi 휴대폰이면 1단위 = 1.2px이므로 **105단위**다. 데스크톱·batchmode에서는 0이라 배치가 그대로다(마우스).

- 버튼의 맞는 칸이 그려진 버튼보다 작으면 맞는 칸만 48dp로 키운다. 루트는 투명한 맞는 칸이 되고, 그려진 버튼은 자식 `Face`(색 변화·글자 담당)가 된다.
- 이웃과 겹칠 자리는 맞는 칸을 정해 준다(`Band`).
  - 속도·건너뛰기: y 470–575(시간표 위, 누를 것 없음). 방식·카드 설명·확정: y 575–680.
  - `Proceed`·저장/닫기: y 790–900. 스크롤 패널은 y 788에서 끝난다.
  - 시트 닫기는 목록 반대쪽으로 키운다.
  - 파티는 세 열로 바꿔 필살기마다 107×130을 쓴다.
- 목록(효과 대상·덱 선택·덱·부품·배정·기억 변화)은 맞는 칸을 키우지 않고, 줄 높이를 48dp로 키운다.
- 첫 실행 안내(`MemoryForgeOnboarding`)의 알겠어요·건너뛰기도 같은 값으로 키운다. 머리글 글자 위로만 넓어진다.

**확인.** `ExpeditionUiLayoutPlayModeTests.PhoneTouchTargetsAreFortyEightDpAndEachFaceTakesItsOwnPress`는 `TouchOverride = 105`로 휴대폰처럼 그린다. 안내를 붙이고(시험 전용 PlayerPrefs 키) 실제 짧은 탐사를 여러 seed로 끝까지 진행한다. 확인한 화면은 아래와 같다.

- 지도, 2명·5명 전투, 보스 3종, 효과 대상 시트, 턴 결과, 전투 마지막 행동 시트.
- 보상, 엘리트 보상, 휴식, 덱 선택, 공방, 상점, 사건, 저장, 결과.
- 덱·기록·포기·카드 설명 시트.

각 화면의 맨 위 층에서 확인하는 것은 세 가지다.

1. 모든 버튼의 맞는 칸이 양쪽 105단위 이상이다.
2. 서로 다른 버튼의 맞는 칸이 겹치지 않는다(스크롤 안은 보이는 만큼).
3. 그려진 면의 가운데와 네 귀퉁이 안쪽 20% 지점이 실제 레이캐스트에서 그 버튼으로 간다.

모든 band를 끄면(가운데 기준 확대만 하면) 이 시험이 덱 시트에서 겹침으로 실패한다. 즉 겹침 검사가 실제로 잡는다(뮤테이션 확인).

실기기 측정(노치·글자 배율 115/130%)과 Codex 명세의 "접근성 행 배치"(서랍형 손패 등)는 후속이다.
