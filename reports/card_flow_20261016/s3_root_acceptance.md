## Behavior

The list drawn by PickSheet and accepted by PickCard is the shared PickCandidates query. It selects the current hand/discard/reservation zone, excludes the source hand card and prior picks, and applies the existing growth filter. Readonly PickerPicks/PickerOptions return detached results. Invalid/out-of-zone/source/repeated inputs cannot append or send.

A sheet stores its opening Run reference/node/battle version/target. Before a pick/auto send and on render/resume, the same context, player phase and hand source must still exist. A stale sheet closes unsent with PICK_STALE. No fallback request, refund or target substitution occurs. Explicit Auto preserves Core's existing automatic remaining-picks rule. This does not redefine its semantic target predicates: the prototype's displayed list can still be broader than a particular effect's Core predicate (for example rarity-C tune targets); that existing boundary is documented in the author report and is not claimed fixed here.

Recovery and turn-summary gates remain first. Every unrelated normal command/selection, including direct Play/End/Ult/Do/save/depart, refuses before reaching Run while the picker is open. Its own Pick/Auto/Cancel have explicit ownership. The sheet closes before its one final play, so that request passes the common gate exactly once. Cancel keeps ordinary card/mode/target selection and clears only that sheet's refusal code. Existing inactive-button callback checks remain in force.
