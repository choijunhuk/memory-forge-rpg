# 전용 아트·새 탐사 균형2

유리·리엔·카야 전신3/SD3를 기존 브리프대로 제작해 연결했다. 니아는 기존SD로 홈 선택이 가능하다. [원본과 프롬프트](../../art/generated/roster-completion-20261023/README.md), [아트 검증](art-verification.json), [독립 검토](art-independent-review.json), [실제 컴퓨터 수용](computer-acceptance.json)을 구분한다.

새 계정 스토리 출발에만 적 체력130%·피해110%의 불변 설정을 기록한다. 기존 Run/진행 원장에 새 멤버가 없는 기록은100/100과 원래 JSON 모양을 유지한다. 새 기록은 출발 스냅샷과 원장 양쪽에 같은ID/해시를 고정한다. 한쪽을 지우고 난이도/생성 해시를 바꾼 경우도 전체 기록 검증에서 거절한다. 기존 영수증 본문·기억·파티·경제 정책은 보존한다.

[같은 조건 전후 비교](balance-validation.json)는 기존 목표/60턴 관찰 한도와 전체 결과 분모를 사용한다. 조정 표본882회, 분리 반복2709회에서 지표 이탈0이다. greedy와 같은 planner를 독립 정책으로 세지 않는다. 무작위 소멸 선택으로 공격 수단을 잃은1사례는 중단으로 포함하며, 동일 시작 상태의10턴 승리 전략도 검사한다. 후보의 작은 부분 표본 이탈1과 미구현 후반3–5장 후보 이탈7은 정보로 남긴다.

재현: `node tools/review/expedition_balance.mjs`. 잘못된 설정·기존 목표 이탈·진행 가능한 전략 증인이 없는 중단은 비영 종료로 CI를 막는다. 기존 `balance_probe`와 고정 참조 데이터는 변경하지 않았다. 사람 플레이 균형 인증으로 확대하지 않는다.

[서버·저장 검증](balance-verification.json), [양방향 독립 검토](balance-independent-review.json)를 참고한다. 튜토리얼/성장/주간보스/기존 연습 경로는 원래 배율이다. 폰은 사용자 요청으로 제외했으며 실제 Android 에뮬레이터의 익명 화면 입력과 PC 네이티브 홈 표시를 확인했다. PC 자동 포인터 입력은 도구 제약으로 수용하지 못했다.

## 기존 저장에 쓸 실행기

Core 소스가 같아도 .NET 빌드는 Git 커밋 표시가 달라지면 DLL/MVID가 바뀐다. 소스 동일성을 저장 호환 증거로 취급하지 않는다. 이 검증은 등록된 정확한Core(`65bc74a…`)를 바이트 그대로 보존한 새 서버에서 기존 개발 저장을 읽기 전용 검증했고 파일 바이트/수정 시각을 유지했다. 미등록 Core의 소유자 이관은 계속 거절한다. 바인딩 헤더를 수정하지 않는다.

비추적 로컬 결과: `ops/ai/local/art-balance-phase2-20261023/`의 PC앱·APK·새서버/등록Core 조합·원시 시험 로그. 공유 저장소에는 인증/계정 파일을 넣지 않는다. 최신 원격 성공은 PR #2의 정확한 SHA별 검사 결과로 확인한다.
