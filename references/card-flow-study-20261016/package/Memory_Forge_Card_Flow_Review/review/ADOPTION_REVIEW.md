# 기억 공방용 card-flow-study 검토 및 선택 반영안

검토일: 2026-10-16. 대상: 사용자가 제공한 `card-flow-study.zip`의 문서와 독립 TypeScript 예제. **기억 공방의 현재 원격 저장소를 검사하거나 수정한 결과가 아니다.** 기존 대화의 설계 방향을 기준으로 참고 가능성을 평가했다. 실제 개발 시에는 최신 승인 결정과 코드부터 대조해야 한다.

## 1. 결론

**전달할 가치가 있다. 주된 용도는 새로운 전투 규칙 도입이 아니라 카드 조작·연출·오류 복구·회귀 시험 보완이다.**

원본 파일 16개를 변경하지 않고 함께 보관했다. 이번에 새로 쓴 것은 검토서·시작 지시문·독립 진단 재현·실행 기록이다. 게임 전체 설계서나 개발 패키지를 교체하는 파일이 아니다. 원본 소스의 버그를 수정하거나 기억 공방에 이식한 것도 아니다.

### 추론을 사실로 승격하면 안 되는 부분

`01-research` H-03/04/05/06/17은 정확한 해결 순서·일반 입력 예약·시뮬레이션 방식·서버 대기를 확정하지 않았다. `03`의 정산 후 틱, K=2, 카드 비행 250ms, 타격 180ms는 독립 설계/가상 데모 값이다. 카제나 실측값이 아니다.

`02` T-06의 “로그가 타격마다 나타나면 로직도 타격마다 진행” 판정은 단정적이다. 로직이 먼저 계산되고 로그만 연출에 맞춰 출력되는 구조에서도 같은 화면이 나온다. 화면 녹화로 확인할 것은 로그·표시·입력의 타이밍이며 내부 실행 구조는 미확인으로 남긴다. 첫 수락 입력 시각 역시 정확한 개방 시점 자체가 아니라 마지막 거절과 첫 수락 사이의 구간을 준다. 3회 일치는 해당 조건의 반복 관찰이지 모든 모드·카드에 대한 증명이 아니다.

## 3. 기억 공방에 가져올 우선순위

다음은 **검토자의 적용 제안**이다. 원본 카제나의 구현 사실이 아니다. 기존 구현에 이미 있는 것은 재작성하지 않는다.

| 우선순위 | 참고 요소 | 기억 공방 적용 | 완료 증거 |
|---|---|---|---|
| 높음 | Sim/Presenter 분리 | 서버/규칙 코어가 결정하고 화면은 승인 이벤트를 재생. 애니메이션 콜백으로 피해·재화를 확정하지 않음 | 같은 명령의 배속별 최종 상태·결과 일치 |
| 높음 | 연출 백로그·입력 게이트 | 재생 중 1묶음+후속 1묶음 K=2를 초기 비교안으로 시험. 미전송 의도와 승인 후 대기는 구분 | 이중 사용·이중 차감 없음, 거절 이유 표시 |
| 높음 | 중요한 구간의 입력 잠금 | 선택창·예약 일괄 해결·적 행동·턴/결과 전환에서는 명시적 배리어. 실패/타임아웃 해제 경로도 명시 | 누락 이벤트·앱 복귀 뒤 영구 잠금 없음 |
| 높음 | 표시와 실제 상태 구분 | 승인된 사망은 연출 전이어도 선택 불가. 아직 공개되지 않은 드로우 결과는 표시/선택 불가 | 오래된 대상, 새 손패 노출, 비용 UI의 경계 시험 |
| 높음 | 사용/발동 및 효과 출처 | 명령·예약 등록·예약 해결·메아리/복제·반격·유물·소멸을 구분하고 기존 패시브 의미를 보존 | 한 번 발동할 게 두 번 발동하지 않음, 횟수 상한 보존 |
| 중간 | 선택의 데이터화 | pending choice ID·옵션·이어갈 상태를 서버에서 유지. 선택 표시 전 입력과 중복 선택 방지 | 선택 직후 통신 끊김/재시도/복귀 결과 일치 |
| 중간 | 스냅샷 복구 | 되돌리기 아이디어를 우선 개발 재현·재접속에 이용. 전체 공개 UI 상태 재구축 | 손패·AP·의도·예약·성장·부채·게이지 일치 |
| 중간 | 관찰 프로토콜 | 외부 게임 추가 조사에 개발을 종속하지 말고 기억 공방의 실제 모바일 조작 평가로 전용 | 동일 전투·기기·배속별 입력 지연과 이해도 기록 |

### 가장 중요한 용어 구분

- **시간 예약**: 다음 턴/다다음 턴에 효과를 발동하는 기억 공방의 전략 규칙. 예약 슬롯을 소비한다.
- **입력 대기**: 아직 서버에 제출하지 않은 다음 행동 의도. 이 단계의 취소는 기존 승인 행동을 되돌리는 것이 아니다.
- **서버 확인 대기**: 제출했지만 결과를 확인하지 못한 명령. 재전송은 같은 request ID를 쓰며 클라이언트가 임의 취소·환불하지 않는다.
- **연출 대기**: 서버 승인까지 끝났고 화면 재생 순서만 기다리는 묶음. 시간 예약 슬롯과 무관하다.

원본 I-02의 “사용 예약”을 기존 미래 예약과 같은 자료구조로 합치면 안 된다. K 역시 우선 연출 묶음 수의 제한이다. 서버에 동시에 던질 미승인 명령 개수나 미래 예약 슬롯 수가 아니다.

### 서버 권위와 결합하는 초기안

서버 확인 대기 명령은 우선 1개로 두고, 이전 승인 연출이 끝나기 전 다음 명령을 보낼 수 있게 한다. 아직 전송하지 않은 카드는 의도로 표시하고 비용을 확정 차감하지 않는다. 승인 후에는 현재 AP/가용 카드/대상을 즉시 동기화하면서 피해 숫자와 동작은 이벤트 시각에 맞춰 재생한다. 사용 불가 사유를 숨기지 않는다.

원본 예제는 전체 로컬 Sim과 RNG에 접근한다. 이를 그대로 사용해 미래 손패·서버 난수를 클라이언트가 읽게 하지 않는다. 수치 미리보기와 확정 이벤트를 구분한다. 네트워크 연동, 권위 상태, 멱등 처리는 이 예제의 구현 범위 밖이다.

## 4. 그대로 도입하지 않을 것

1. **적 퓨즈를 기본 전투로 바꾸기.** 기존 기억 공방은 미래 턴 예약과 턴 종료 적 행동의 상호작용이 중심이다. 퓨즈는 카드 수를 추가 자원으로 만들어 잔향·0비용 카드·계약·예약의 가치를 바꾼다. 별도 엘리트/보스 실험 제안은 가능하지만 전체 엔진 변경의 근거는 부족하다.
2. **AP 3·경직 보상·다단 타깃 정책·피니셔·RNG 교체.** 모두 예제의 선택이다. 기존 AP/균열/재지정/전투 종료 명세를 우선한다.
3. **무제한 플레이어 되돌리기.** 재현용 스냅샷과 유저 상품 기능은 다르다. 온라인에서의 숨은 정보·보상·정책을 별도 결정해야 한다. 자동 전투도 I-08은 명세만이며 즉시 출시 기능으로 추가하지 않는다.
4. **클라이언트 선확정 후 사후 검증으로 전환.** 원본이 네트워크를 구현한 것이 아니다. 기억 공방의 서버 판정·원장·비공개 난수를 유지한다.
5. **예제 엔진 전체 이식.** 단일 hero와 7개 EffectSpec 종류 중심의 예제다. 3인 카드 소유·예약·개조·진화·계약·장비가 있는 현재 코어를 대체하지 않는다. 필요한 패턴을 기존 구조에 맞춰 보강한다.

## 5. 독립 검사에서 확인한 사항

### 기존 시험과 형식 검사

- 입력 ZIP: 20개 엔트리 중 파일 16개. 원본 파일을 새 패키지에 그대로 복사하고 SHA-256 대조 완료.
- 환경: Node v22.16.0에서 `--experimental-strip-types`로 원본 테스트를 실행했다. 원문이 권장한 Node 23.6+ 환경 자체를 재현했다고 주장하지 않는다.
- 원본 시험: **27/27 통과**. `review/original-tests.tap`.
- 타임라인 데모: 종료 코드 0. `review/demo.txt`. 이것은 가상 시계 로그이며 화면을 사람이 플레이한 것이 아니다.
- TypeScript 5.8.3: 원래 설정 그대로는 이 환경에 프로젝트용 `@types/node`가 없어 실패했다. 이미 설치된 Node 타입 경로를 `--typeRoots`로 제공한 검사에서는 통과했다. 소스 타입 결함으로 잘못 분류하지 않는다. 첫 실패 로그도 보존했다.
- Unity/실기기/네트워크/실제 카제나 플레이: **미실행**. 실제 게임의 내부 순서나 체감 품질을 검증했다고 말하지 않는다.

### CF-01 — 턴 종료 반응과 손패 정리 순서 불일치

근거: `03-design-spec.md` §8(196행 이후), `prototype/src/engine.ts` `endTurn`(431행 이후).

명세는 `TurnEnding` 반응 → 손패 정리 → 적 행동 → 새 턴 순이다. 실제 `endTurn()`은 이벤트만 emit하고 곧바로 손패를 버린 후, `afterStep()`에서 반응을 실행한다.

유효한 합성 `TurnEnding: draw 1` 반응, 턴 드로우 1, 보존 카드 없음으로 검사했을 때:
- 명세 순서라면 종료 반응으로 뽑은 카드도 정리되고 새 턴 손패는 1장이어야 한다.
- 실제 이벤트는 `TurnEnding → CardMoved(hand→discard) → ReactionTriggered → CardDrawn → TurnStarted…`이며 손패가 **2장** 남는다.

이는 기본 예제 카드로 플레이하다 발견한 문제가 아니라, 지원되는 범용 반응 훅에 합성 효과를 넣은 경계 검사다. 해당 설계를 채택할 때 정리 단계를 별도 Op로 분리하거나 명세를 의도적으로 수정해 순서를 맞춘다. 원본 파일에는 패치를 하지 않았다.

### CF-02 — 연산 상한 초과 후 부분 결과가 남는 정책

근거: R-15(120행), `engine.ts` `abortResolution`(588행 이후), 기존 `feedbackLoop` 시험용 카드.

연산 한도 200에서 무한 방어 반응을 실행하면 AP 3→2, 방어 0→**105**, 적 퓨즈 **98 유지**, `phase=playerMain`이 된다. 상한 초과 이벤트를 내고 미처리 틱·인터럽트를 버리면서 이미 받은 방어는 보존한다.

**원본이 그렇게 명세한 정책이므로 R-15 구현 버그라고 부르지 않는다.** 그러나 온라인 게임에서는 오류로 얻은 이익과 미해결 페널티가 함께 남는 구조가 된다. 기억 공방에서는 원자적 실패/롤백 또는 복구 필요 상태로 전환해 이후 입력·보상을 막고 서버와 복구해야 한다. 선택 대기를 넘는 연쇄에는 논리적 행동 단위 한도도 검토한다.

### CF-03 — 아무 카드 없이 턴 종료를 반복할 수 있는 기본값

근거: `03` §6, `DEFAULT_RULES.fuseTickAtTurnEnd=0`.

숫자 퓨즈만 가진 적에게 카드 없이 턴 종료 10회를 실행한 결과 1턴→11턴, 적 행동 0회, HP 50 유지, 퓨즈 1 유지였다. **문서도 이미 인정한 기본 규칙이지 숨겨진 신규 버그가 아니다.** 미래 예약이 핵심인 기억 공방과 섞으면 적의 압박 없이 턴을 보내는 상호작용이 생길 수 있으므로 도입하지 않는 편이 낫다. 실제 기억 공방에서 그 상호작용을 실행한 것은 아니다.

재현: `review/independent-probes.ts`, 결과: `review/independent-probes.json`. 세 진단은 관찰한 동작을 assert하는 재현이지 제품 승인 테스트 3개를 추가 통과했다는 뜻이 아니다.

## 6. 이식 인수 기준 제안

- 같은 승인 명령열을 1배/2배/연출 생략으로 재생해 최종 공개 상태·전투 결과가 일치한다.
- K 제한, 다중 탭, 같은 카드 중복 입력, 서버 미응답 중 추가 입력을 구분한다.
- 첫 공격으로 확정 사망한 대상 재선택에 비용이 추가 차감되지 않는다.
- 선택창 표시 전 입력, 같은 선택 재전송, 앱 복귀 시 이전 선택창이 새 선택을 덮는 경우를 시험한다.
- 미래 예약 등록/해결과 입력 백로그를 독립적으로 검사한다.
- 메아리·복제·유물·반격·소멸의 출처와 횟수 상한을 원본 전투 명세와 대조한다.
- 연출 콜백 유실·건너뛰기·화면 전환 뒤 배리어가 영구 유지되지 않는다.
- 상태 복구가 손패뿐 아니라 AP·방어·예약·부채·성장·게이지·적 의도까지 동기화한다.
- 연산 상한 오류가 부분 보상 지급이나 적 행동 회피를 허용하지 않는다.
- 작업 단위마다 상대 AI가 독립 리뷰하고, 실제 Unity 검증과 헤드리스 결과를 분리해 남긴다.

## 7. 전달 방법

새 참고 ZIP 하나와 루트 `START_CODEX_MESSAGE.txt`를 현재 개발 중인 Codex 채팅에 전달한다. Codex가 원문과 검토를 Claude에게도 전달하게 한다. 기존 게임 전체 ZIP을 다시 풀거나 프로젝트를 초기화하지 않는다. 반영한 항목만 최신 설계 원본·시험·코드에 동기화한다. 이 검토를 위해 실제 게임 파일·에셋·계정 비밀을 추가로 제공할 필요는 없다.
