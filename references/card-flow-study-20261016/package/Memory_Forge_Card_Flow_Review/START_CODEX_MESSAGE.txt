첨부한 Memory_Forge_Card_Flow_Reference.zip을 기억 공방의 추가 참고자료로 검토하고, 도움이 되는 부분을 현재 개발에 반영해.

이 ZIP은 게임 전체 패키지나 새 기준 설계서가 아니다. 기존 프로젝트·진행 중 작업·최신 승인 결정을 유지한다. 먼저 README_REVIEW.md → review/ADOPTION_REVIEW.md → card-flow-study/README.md와 01·02·03 문서 → 관련 코드를 읽어라. 원본 자료는 references/card-flow-study 같은 별도 참고 경로에 보관하고, prototype의 package.json이나 엔진을 프로젝트 루트에 덮어쓰거나 런타임 의존성으로 추가하지 마.

[자료 해석]
01-research는 공개 자료 조사, H-항목은 미확인 추정, 02는 아직 수행되지 않은 관찰 계획, 03과 TypeScript 코드는 분석자가 만든 독립 설계다. K=2·클립 시간·퓨즈·해결 순서를 카제나의 실제 내부 구현이라고 취급하지 마. 공식 자료의 일부 사례로 전체 게임의 일반 규칙을 단정하지 마.

[우선 반영할 것]
1. 카드 효과 판정과 연출을 분리하면서, 연출 중 다음 행동을 준비할 수 있도록 입력 흐름을 개선한다. K=2는 '재생 중 1묶음+후속 1묶음'의 시험 시작값일 뿐 강제 완성값이 아니다.
2. 기억 공방의 다음 턴/다다음 턴 '시간 예약'과 같은 턴의 '입력 대기/연출 대기'를 명칭·자료구조·UI에서 분리한다. 후자가 미래 예약 슬롯을 점유하면 안 된다.
3. 선택창·적 행동·미래 예약 해결·턴 경계·전투 종료에서 어떤 입력을 잠글지 명세한다. 승인된 상태에서는 이미 죽은 대상이나 이미 사용한 카드를 다시 선택하지 못하게 하고, 재접속·오류·연출 중단 뒤 입력 잠금이 남지 않게 한다.
4. 카드 사용, 예약 등록, 예약 해결, 효과 발동, 복제, 소멸, 유물/반격을 구별해 각 패시브·횟수 제한이 어느 사건에 반응하는지 확인한다. 기존 이벤트와 코어를 재사용하고 필요 없는 범용 엔진 재작성은 하지 마.
5. 배속·연출 생략에 따라 전투 결과가 바뀌지 않도록 하고, 복귀 시 서버의 공개 상태로 화면을 다시 구성한다. 유저용 되돌리기나 자동 전투는 이 자료만으로 새로 출시 기능에 추가하지 마.

[그대로 가져오지 않을 것]
AP 3, 퓨즈 카운트, 경직 보상, 피니셔 강제 턴 종료, 무제한 되돌리기, 대상 재지정 방식, 리셔플 규칙과 RNG를 원본 예제대로 교체하지 않는다. 특히 퓨즈를 기본 전투에 추가하면 기존 예약·잔향·계약·밸런스가 달라진다. 필요성은 별도 제안으로 남긴다.
기억 공방의 서버 권위·재화 원장·난수 비공개 원칙을 유지한다. 로컬 Sim이 미래 결과를 먼저 안다는 예제를 서버 승인 없는 선행 확정으로 옮기지 마. 미전송 의도, 서버 확인 대기, 승인 후 연출 대기를 구분하고 비용은 한 번만 처리한다. 초기에는 서버 미응답 명령 1개를 기준으로 안전하게 검증해라.

[검증에서 발견한 사항]
제공 코드의 27개 시험은 통과했지만, review/independent-probes.ts는 턴 종료 반응이 손패 정리 뒤에 실행되는 명세 불일치, 연산 한도 중단 뒤 방어 105와 미처리 퓨즈가 남는 부분 확정 정책, 카드 없이 10턴을 넘겨도 퓨즈 적이 행동하지 않는 기본값을 재현한다. 뒤 두 항목은 원문이 정한 정책의 위험이지 명세 위반 버그로 분류한 것이 아니다. 관련 패턴을 채택하기 전에 대조하고, 연산 오류는 부분 보상을 남겨 정상 진행하지 말고 원자적 실패 또는 서버 복구 필요 상태로 처리한다.

[개발 진행]
현재 구현과 대조해 채택/이미 구현/수정 후 채택/보류를 먼저 짧게 기록한 뒤, 효과가 큰 입력·연출 개선부터 실제 구현해. 핵심 전투 규칙 변경은 별도 승인 대상으로 분리하되, 합의된 범위의 UI·테스트·오류 복구 보강 때문에 매번 승인을 기다리지 마.
기능 단위로 작성자가 아닌 상대 모델이 원래 요구사항과 실제 결과를 독립 리뷰하고, 수정·재검증 후 다음 작업을 계속한다. P1 등 단계가 끝났다는 이유만으로 멈추지 마. Unity MCP로 실제 Editor·Play Mode에서 확인하고, 실기기·네트워크 검증과 헤드리스 시험을 구분해라.

기존 Sol·Opus, High/Max 중심, 구독 전용, Codex의 Claude CLI 자동 호출, 이미지 생성·내용 수정 Codex 담당, GitHub Private 정책은 유지한다. 새 결제나 모델 설정 변경 요청이 아니다. 보고는 채택 항목·실제 변경·검증·보류 사유만 짧게, 상세 근거는 저장소에 남겨라.
