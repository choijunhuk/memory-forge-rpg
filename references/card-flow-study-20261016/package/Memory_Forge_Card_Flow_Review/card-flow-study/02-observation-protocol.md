# 02. 플레이 관찰 프로토콜 — 추정(H-xx)을 사실로 바꾸는 방법

[01-research.md](01-research.md) §3의 추정을 **직접 플레이와 화면 녹화만으로** 검증하는 절차다. 결과는 [observation-log.csv](observation-log.csv)에 한 줄씩 적는다.

## 1. 원칙

- **정상 플레이만 한다.** 입력은 손으로 직접 한다. 매크로, 오토클릭, 자동화 도구, 메모리·패킷·파일 분석, 클라이언트 변조는 쓰지 않는다. 약관은 "예정된 방식으로만 이용"을 요구하고, 이런 도구는 안티치트 제재 대상이 될 수 있다.
- **녹화는 일반 도구로 한다.** PC는 OBS(60fps), 모바일은 OS 기본 화면 녹화를 쓴다. 분석은 녹화 파일을 프레임 단위로 넘겨 보면 된다(VLC `E` 키, mpv `.` 키).
- **게임 내 기능은 마음껏 써도 된다.** 전투 로그, 행동 예고 정보창, 자동 전투, '마지막 행동 되돌리기'는 정상 기능이다. 되돌리기는 같은 상태에서 실험을 반복할 때 특히 유용하지만, 매일 충전되는 자원을 쓴다는 점은 감안한다.
- **버전을 기록한다.** 패치마다 동작이 바뀔 수 있다. 날짜, 플랫폼(PC/모바일), 모드, 배속 설정을 같이 적는다.
- **결과가 한 번이면 '관찰', 3회 이상 같으면 '확인'**으로 표기한다.

## 2. 측정 기준점

녹화에서 아래 프레임을 찾아 시각(ms)을 적는다. 60fps면 1프레임이 약 16.7ms다.

| 기호 | 순간 | 찾는 법 |
|---|---|---|
| t0 | 카드를 놓은 순간(드래그 해제) | 카드가 손에서 떨어지는 첫 프레임 |
| t1 | 첫 효과 피드백 | 첫 타격 이펙트나 첫 수치 팝업 |
| t2 | 마지막 효과 피드백 | 마지막 수치 팝업 |
| tc | 적 행동 카운트 숫자가 바뀐 순간 | 카운트 UI를 확대해서 확인 |
| tl | 전투 로그에 해당 줄이 생긴 순간 | 로그 창을 열어 둘 수 있는 경우만 |
| t3 | 다음 카드 입력이 처음 받아들여진 순간 | 아래 '연타 탐침' 참고 |

**연타 탐침:** t0 직후부터 다음 카드를 반복해서 끌어 놓는다. 처음으로 받아들여진 시도(카드가 튕겨 돌아오지 않음, 예약 표시가 뜸, 또는 바로 사용됨)의 프레임이 t3다. 받아들여진 방식(즉시 사용 / 예약 표시 / 거절)도 함께 적는다.

## 3. 테스트 목록

카드나 적 이름은 예시다. 같은 성질(조건·타수·카운트)을 가진 다른 카드로 바꿔도 된다. 카드 문구는 버전마다 다를 수 있으니 테스트 전에 게임 안에서 다시 확인한다.

### T-00 기본 입력 방식 → H-01
- **절차:** 카드를 드래그로 쓴다. 탭으로 쓸 수 있는지 시도한다. 타겟팅 카드를 쓰다가 중간에 취소한다(빈 곳에 놓기, 손패로 되돌리기). PC에서는 단축키 선택도 해 본다.
- **기록:** 쓸 수 있는 입력 방식, 취소 방법, 대상을 지정하는 순서(카드 먼저인지 적 먼저인지).

### T-01 AP 지불 시점 → H-02
- **준비:** 효과 수치가 '현재 AP'에 비례하는 카드. 예: GameWith에 소개된 미카의 *Blessing of Waves*(현재 AP에 따라 회복량 증가).
- **절차:** AP가 정확히 3일 때 사용한다. 회복량이 비용을 낸 뒤 AP(2) 기준인지, 내기 전 AP(3) 기준인지 계산한다. 비교용으로 AP 2일 때도 한 번 쓴다.
- **판정:** 낸 뒤 AP 기준이면 '효과보다 먼저 지불'(H-02 지지).

### T-02 카운트 감소가 효과보다 먼저인가 → H-03
- **준비:** 대상의 행동 카운트를 조건으로 쓰는 카드. 예: GameWith 공용 카드 목록의 *Seven Arms* 계열 문구("대상 행동 카운트 5 이상이면 AP +2").
- **절차:** 대상 카운트가 **정확히 5**일 때 사용한다.
- **판정:** 조건 효과가 발동하면 효과가 감소 전 값(5)을 봤다는 뜻이다(H-03 지지). 발동하지 않으면 사용 즉시 감소(4)가 먼저 적용됐다는 뜻이다.

### T-03 카운트 1인 적을 격파하면 → H-03
- **준비:** 카운트가 1이고 인내가 거의 바닥난 적.
- **절차:** 그 적을 격파하는 카드를 쓴다. tc, 격파 연출 시점, 적 행동 여부를 기록한다.
- **판정:** 적이 행동하지 않으면 격파 +1이 행동 판정보다 먼저 반영된 것이다. 적이 카드 효과보다 먼저 행동하면 '사용 즉시 판정'이다. T-02와 같이 보면 감소 시점을 특정할 수 있다.

### T-04 인터럽트와 후속 트리거의 순서 → H-04
- **준비:** 카운트 1인 적, 그리고 사용 후 추가 효과가 따라붙는 카드(추가 공격, 콤보, '카드 사용 시' 패시브 등).
- **절차:** 카드를 쓰고 전투 로그와 화면에서 순서를 기록한다.
- **판정:** [카드 효과 → 후속 트리거 → 적 행동]인지, 적 행동이 그 사이에 끼는지.

### T-05 사용 예약의 범위 → H-05
- **절차 A:** 타수가 많은 긴 연출 카드를 쓴 직후, 다른 카드를 바로 끌어 놓는다. 이어서 세 번째 카드도 시도한다.
- **기록:** 두 번째·세 번째 카드가 어떻게 처리되는지(즉시 사용 / 예약 표시 / 거절), 예약된 카드의 AP가 언제 빠지는지(예약 시점인지 실행 시점인지), 예약을 취소할 수 있는지.
- **절차 B:** 첫 카드로 쓰러질 적을 두 번째(예약) 카드의 대상으로 지정한다.
- **판정 B:** 예약된 카드가 취소되는지, AP를 돌려받는지, 다른 대상으로 넘어가는지, 아니면 아예 지정이 안 되는지. 이것으로 예약 시점 검증과 실행 시점 재검증을 구분한다.

### T-06 로직이 연출을 기다리는가 → H-06
- **절차:** 전투 로그 창을 열어 둔 채(가능하다면) 긴 다단 히트 카드를 쓴다. 로그 줄이 생기는 시각(tl)을 타격 연출 시각과 비교한다. 배속을 바꿔 같은 실험을 반복한다.
- **판정:** 로그가 첫 타격 전에 한꺼번에 생기면 로직이 먼저 끝까지 계산된 것이다. 타격마다 하나씩 생기면 로직이 연출에 맞춰 진행되는 쪽이다. 배속에 따라 t3가 같은 비율로 줄면 입력 재개가 연출에 묶여 있다는 뜻이다.

### T-07 이번 턴 사용 카드는 리셔플에서 빠지는가 → H-07
- **준비:** 뽑을 더미가 1~2장 남은 상태. 묘지 숫자 옆 '+N' 표시를 확인한다.
- **절차:** 카드를 몇 장 쓴 뒤 드로우 효과로 뽑을 더미를 비우고 한 장 더 뽑는다.
- **판정:** 이번 턴에 쓴 카드가 다시 뽑히는지, 리셔플 뒤 '+N'과 버린 더미 수가 어떻게 바뀌는지.

### T-08 숫자 카운트 적의 턴 종료와 카운트 재설정 → H-08, H-09
- **절차:** 카운트가 남은 적이 있는 상태에서 카드를 쓰지 않고 바로 턴을 끝낸다. 다음 턴 카운트를 기록한다. 그다음 적이 한 번 행동하게 만들고, 행동 직후 새 카운트와 정보창의 다음 행동을 비교한다.
- **판정:** 턴 종료 때 행동했는지, 카운트가 바뀌었는지. 재설정 값이 다음 행동의 값과 같은지.

### T-09 다단 히트 도중 대상 사망 → H-10
- **준비:** 체력이 낮은 적 A와 다른 적 B. A에게 첫 1~2타 안에 죽을 다단 히트 카드.
- **판정:** 남은 타격이 B로 넘어가는지 사라지는지. 전투 로그로 확인한다.

### T-10 여러 적이 동시에 0이 될 때 → H-11
- **준비:** 카운트가 1인 적 둘 이상.
- **판정:** 행동 순서(화면 왼쪽부터인지, 다른 기준인지), 연출이 겹치는지, 로그 순서.

### T-11 Ultimate 태그 → H-12
- **준비:** 현재 버전에 해당 태그 카드가 있을 때만.
- **절차:** 그 카드 뒤에 다른 카드를 예약해 둔다(T-05 방식).
- **판정:** 효과가 끝난 뒤 턴이 끝나는지, 예약된 카드가 어떻게 되는지(취소, AP 반환), 카운트 감소와 적 인터럽트가 턴 종료 전에 일어나는지.

### T-12 번뜩임 선택 UI의 위치 → H-13
- **절차:** 빛나는 카드를 쓰고, 선택 팝업이 언제 뜨는지 기록한다. 카드 효과 연출 전인지 후인지, 카운트 감소(tc)와 적 행동보다 앞인지 뒤인지.

### T-13 '발동'된 카드와 카운트 → H-14
- **준비:** "뽑은 카드를 발동"처럼 다른 카드를 발동시키는 효과.
- **판정:** 적 카운트가 몇 번 줄어드는지(1회인지 2회인지). 발동된 카드가 '카드 사용 시' 패시브를 일으키는지. 발동된 카드가 어느 구역으로 가는지.

### T-14 전투 배속 → H-15
- **절차:** 일반 전투 UI와 설정에서 배속 토글이 있는지 확인한다. 있으면 1배속과 최대 배속에서 같은 카드의 t0→t3를 잰다.

### T-15 손패가 가득 찼을 때 드로우 → H-16
- **절차:** 손패 10장 상태에서 드로우 효과를 쓴다. 뽑힌 카드의 행방(버린 더미 수 변화, 연출)과 '드로우했을 때' 계열 효과가 발동하는지 기록한다.

## 4. 기록 양식

[observation-log.csv](observation-log.csv)를 스프레드시트로 열어 쓴다.

| 열 | 내용 |
|---|---|
| test_id | T-00 ~ T-15 |
| date / game_version / platform / mode / speed | 환경 |
| setup | 시작 상태(AP, 카운트, 손패, 대상 체력·인내) |
| action | 한 행동 |
| t0_ms … t3_ms | §2의 기준점(없으면 비워 둠) |
| observed | 관찰한 결과(있는 그대로) |
| interpretation | 어느 가설을 지지·반박하는지 |
| repeats | 같은 결과가 나온 횟수 |
| video_file | 녹화 파일과 타임코드 |

결과가 모이면 01-research.md §3의 해당 행을 §2로 옮기고, 등급을 'O(직접 관찰)'로 적는다.
