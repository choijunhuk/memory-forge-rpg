## 요약

**확인된 사실** (공식 공지 근거)
- 카드를 한 번 쓰면 적 행동 카운트가 1 준다(F-09). 에고 스킬은 카운트를 줄이지 않는 것이 정상이다(F-10).
- 연출이 재생되는 도중에도 다른 카드를 쓸 수 있었다(F-14). 게임 안에 **'사용 예약된 카드'** 개념이 있다(F-15).
- 진행이 연출 완료에 묶인 구간이 있다(F-17). 수치는 연출 타이밍에 맞춰 갱신하는 것이 의도다(F-18).
- 해결 도중 선택 UI가 끼어들 수 있다(번뜩임, 카드 선택 스킬). 선택하기 전까지 진행이 멈춘다(F-32, F-33).
- '발동'과 '사용'은 다른 개념이다(F-13). 피해에는 출처 속성이 붙는다(F-21). 구역 이동이 트리거가 되고(F-22), 턴당 횟수 제한이 있다(F-23).
- 되돌리기(마지막 행동 / 현재 턴)가 있고, 복원한 뒤 화면이 어긋나는 버그가 반복됐다(F-34).

**추정** (관찰로 확인 필요)
- 카운트 감소와 적 인터럽트는 현재 카드의 효과가 해결된 **뒤에** 일어난다(H-03, H-04).
- 사용 예약은 연출 중 입력에 대한 일반 동작이고, 실행 시점에 다시 검증한다(H-05).

**새 설계** (03-design-spec)
- 로직이 먼저 즉시 끝까지 해결되고 연출은 그 결과를 재생한다. 그래서 결정론, 되돌리기, 리플레이를 보장할 수 있다.
- 입력 개방 조건: `Sim 대기 상태 ∧ 배리어(적 행동·선택·턴 전환) 없음 ∧ 백로그 < K(기본 2)`
- 곧 죽을 적은 화면에 보여도 대상으로 고를 수 없다(확정 사망 표시). 낡은 화면을 보고 한 입력이 엉뚱하게 처리되는 일을 막는다.
- 템포 틱(퓨즈 -1)은 카드 **정산 뒤**에 일어난다. 그래서 같은 카드의 경직 +1이 먼저 반영된다.

## 실행

Node 23.6 이상(타입 제거 기본 지원)이면 설치 없이 바로 돈다. 이 PC에는 Node 24.20이 있다.

```bash
cd card-flow-study/prototype
```

```bash
npm test
```

```bash
npm run demo
```

| 파일 | 역할 |
|---|---|
| `src/types.ts` | 상태·이벤트·명령 타입. 상태는 직렬화 가능한 데이터만 담는다. |
| `src/engine.ts` | Sim: 검증 → 커밋 → 해결 큐 → 정산 → 템포 → 인터럽트 → 턴 경계 |
| `src/presenter.ts` | 헤드리스 연출 타임라인과 입력 게이트(백로그, 배리어, 확정 사망 표시) |
| `src/cards.ts` | 예시 카드·적·반응. 전부 새로 만든 것이다. |
| `src/demo.ts` | 가상 시계로 입력과 연출 타임라인을 출력한다. |
| `test/*.test.ts` | 명세 규칙 번호별 테스트 |

## 하지 않은 것

- 설치된 레퍼런스 클라이언트의 파일, 에셋, 메모리, 통신은 열거나 분석하지 않았다.
- 원본 코드, 데이터, 에셋, 고유 용어를 가져오지 않았다. 프로토타입의 이름과 수치는 모두 독자적이다.
- 관찰 프로토콜도 정상 플레이와 화면 녹화로 한정했다. 매크로, 자동화, 변조는 쓰지 않는다.
