## Shared API being implemented by Codex
- MF.MemoryV2.baseline(DATA, cid): base specs with canonical stable keys.
- MF.MemoryV2.cost(DATA, cid, specs, baselineSpecs): full-result cost (baseline optional for legacy proposal compatibility).
- MF.MemoryV2.migrate(DATA, legacyMemoryMap, capacities): pure deterministic dry-run returning record {schema:'mf-memory-v2',version:0,memory:{cid:[stable specs]},quarantine:{cid:{code,original}},legacyBackup:deepCopy(legacy),history:[],receipts:{}}. Invalid/over-capacity decks are quarantined, never truncated.
- Run.create(DATA,{party,memory:record.memory,memoryPolicy:'v2',memoryVersion:record.version,runId:<unique string>,...existingSetup}). v2 is opt-in; legacy tests retain default legacy. For useMemory:false, provide persistent before as setup.memory as usual plus useMemory:false; engine uses base kit for play but keeps before for saving.
- run.s.memoryVersion and run.s.runId hold expected version/run identity.
- run.memoryChanges(): per cid {capacity,usedBefore,before:[spec],after:[spec],changes:[{id,cid,key,kind,value,label}]}. kinds: add/remove/evolve/upgrade/part. Changes have stable delta IDs; display label and full-result preview costs, do not sum costs.
- run.previewMemory(selectedChangeIds): PURE {memory:{cid:[spec]},used:{cid:number},capacities:{cid:number},error:null|'OVER_CAPACITY'|'DEFEAT_KEEP_ONE'}. Invalid IDs throw; valid but too many/over-capacity gives preview + error. No run mutation.
- run.commitMemory({requestId,expectedMemoryVersion,runId,selectedChangeIds},currentMemoryRecord): returns {state:newRecord,response:{memory:partyMap,used,version}}. Does not mutate input record; does finish the called run only on success. Same request/body returns same response before phase/version rejection; changed body conflicts REQUEST_CONFLICT; stale version VERSION_CONFLICT. Other errors: INVALID_SELECTION, INVALID_SNAPSHOT, IDENTITY_REQUIRED, INVALID_CARD/PART/ASSIGNMENT/EVOLUTION, OVER_CAPACITY, DEFEAT_KEEP_ONE, WRONG_PHASE, RUN_MISMATCH.
- To avoid live mutation when localStorage fails: commit using new MF.Run(DATA,JSON.parse(JSON.stringify(app.run.s))) as candidate, persist returned state first, then update live app.run/app.memoryState/app.memory. A failed local write leaves original memory and run untouched.
